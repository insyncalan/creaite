Branch `sprint-peek-new`, worktree `../creaite-peek-new`, from `main` after `sprint-peek` has merged (it has). For v1.4.0; `VERSION` unchanged. Read **BL-179** in `dev/BACKLOG.md`, BL-176 and BL-177, the "Sprint peek" section of `dev/BUILD.md` (how the peek stages, ⌘↵, the chips and pickers), the mockup `dev/mockups/work-item-peek-mockup.html` (the empty state should look like the mockup's peek with an empty title and default chips), and the UX baseline in BUILD.

## The build, one commit each, in marked blocks (`/* ===== BL-179 (sprint-peek-new) ===== */`)

1. **The empty peek.** New action, New risk or issue, and the Decisions New menu's Record a decision and Ask for a decision open the peek empty, with the cursor in the title and the defaults BL-179 lists. The old Create form is no longer opened for actions, RAID items or decisions (milestones and project health keep theirs).
2. **First commit and the one new proposal.** Committing the title with a project set stages one "new" proposal through the route the Create form uses, with the same validation. Edits before it is applied update that proposal; ⌘↵ commits, applies and closes; once applied, the peek switches to the item's ID and its normal behaviour without closing.
3. **Leaving early and reloads.** Esc or a click away on an empty peek stages nothing. With a title but nothing staged it asks Keep or Discard. An unstaged new item survives a reload (reuse BL-167's draft store, keyed for a new item as the Create form was).
4. **Docs for BL-179.** Help, the spec, BUILD ("Sprint peek-new" with the FR text), one line under "## New" in `dev/release-notes/1.4.0.md`.
5. **BL-180: errors as a banner, not a header link** (added by Alan, 11-10-2026), in its own commit and marked block (`/* ===== BL-180 (sprint-peek-new) ===== */`). Build it as BL-180 in `dev/BACKLOG.md` sets out: the header's "n errors in the last day" link goes; a quiet banner with Investigate, Ask creaite to look (only with the live server; read-only) and Dismiss; dismissal remembered in this browser until a newer error; repeats grouped; it stacks under the other page banners, errors last. Its tests are in `test_debug_log_wiring.py` as BL-180 lists. `live_server.py` changes only if the diagnostics route lacks the grouped counts or the newest time. Add a line under "## Changes" in the 1.4.0 notes.

6. **BL-181: a weekend date always raises an alert** (added by Alan, 11-10-2026), last, in its own commits and marked blocks. Build it as BL-181 in `dev/BACKLOG.md` sets out, with these defaults for its "to confirm" points: **milestone dates are left out**, and the **"weekend due date" early warning is on by default** (switchable with the others). The "edit panel" in its list is now **the peek's date chips** (BL-176, and the empty peek from item 1), plus Quick Capture, the cell editor, the Board prompt, the bulk bar, typing a date and the calendar popup: one helper (`weekendNote`) for all of them. It is an alert, never a block. Engine parts: a `weekend` note in `tracker.py` used by `propose.py` and `review.py` (no rejection, no schema change), the warning in `build_dashboard.py`, `work.weekend_days` in `settings-defaults.json`, and one line each in the cx-minutes and cx-sweep skills (prefer a working day; never invent a weekend date). Add lines to the 1.4.0 notes.

7. **BL-185: the status cockpit refined** (added by Alan, 11-10-2026), last, in its own commit and marked block. Build it as BL-185 in `dev/BACKLOG.md` sets out: the cockpit status line's "No due date" metric goes (only that metric: the project page's **No due date card** (FR-95, with its inline date setting) stays); "Due 7 days" becomes "Due 7d" and "21 days" "21d"; the alert metrics get a warning icon. **The icon comes from the shared set through `ic()` (BL-158), not a typed ⚠ glyph** (the icon rule: no typed glyphs on controls), with the metric's words kept so it is never colour or icon alone; add the icon to the set if it isn't there. Every metric stays one click target to its detail.

## Rules

- **Reuse, don't rewrite:** the Create form's validation and staging route, the peek's chips and pickers, BL-167's draft store. No new server route unless the existing one can't stage a new item, and if so say why in BUILD.
- **No schema change.** No `tracker.py` change for BL-179 or BL-180; BL-181's small `weekend` note in `tracker.py` is the one allowed change (a note, never a rejection).
- **Look at it** in the real browser (`dev/tests/live_browser.py`, `dev/tools/cdp.py`) at 1400px, 1100px and 900px, chat open and closed, light and dark, in at least two themes, beside the mockup. Keep the screenshots.
- **Tests:** one pass is enough; your own tests and the files that open New (search the tests for `#newBtn`, `openNew(`, `newDecNeeded`). Tests also run on GitHub's Linux runner: wait for conditions, and don't rely on hover, macOS scrollbars or a native list's keys.
- **The usual edit rule:** don't edit `dev/BACKLOG.md`, `dev/BRD.md` or `dev/archive/sprints/STATUS.md`. Never push or merge.
