## What was built

- **`system/scripts/backup.py`** (new; standard library, Python 3.9):
  - **Daily zip** `system/backups/creaite-backup-YYYY-MM-DD.zip`, made after the daily database backup: the day's closed backup as `system/tracker.db` (never the live file), `system/config/`, `.claude/settings.local.json`, the root `CLAUDE.md`, `system/staging/` minus `ask/` and `uploads/ask/`, `vault.bundle` (`git bundle create --all`; recorded as missing, not a failure, when the vault has no git history), `system/history/flow-*.json`, `processed.txt`, and `manifest.json` (each file's size and SHA-256, the day, the creaite version, the bundle's state). Written as `.creaite-backup-….zip.part` and renamed.
  - **OneDrive copy** of the newest zip into `locations.offsite_backup`, again `.part` then rename. OneDrive unreachable: nothing stops, the line says the copy is made the next day it can be. `tracker.offsite_copy / offsite_dir / last_offsite_copy` are now thin wrappers over it; the "latest 14" rule is gone. The old `tracker-*.db` copies there age out under the daily retention.
  - **Retention** (`backups.*`, defaults in `settings-defaults.json`, catalogue rows under Safety): daily db backups and zips (here and in OneDrive, old OneDrive db copies too) every day for 30 days, then the week's earliest (the Monday) for 365 days, then the month's earliest (the 1st) for good. A month's 1st is kept through the weekly year as well; without that it would be gone before it could be kept for good. Apply/undo/revert/migrate/restore copies 14 days; dashboard snapshots 30 days then the month's first; flow files for good; release zips: the installed one and two before it (newer ones kept; nothing removed if the installed zip isn't there); update backups: the last 3 (only folders holding `update.json`); file-change backups 90 days (date from `files-log.jsonl`).
  - **Tidy up**: once a day after the backup and zip, automatically; exact name patterns in their own folders only, never a symlink, never the newest of a kind, refused in the development repository, skipped when that day's zip failed. Logged as counts and sizes; the last run is kept in `system/backups/backup-state.json`.
  - **Restore check**: once a week (and `backup.py check`): integrity_check on the newest daily backup and the newest zip's database, the zip against its manifest (missing, unlisted or changed files, names outside a backup), and the bundle (`git bundle verify`, then `unbundle` in a scratch repository, which catches a damaged pack).
  - **Restore** (`backup.py restore <zip|date> [--claude-md] [--dry-run]`): checks the zip first; the database through SQLite's backup after a `tracker-<time>-restore.db` copy of the current one, then `tracker.py migrate`; settings.json with the update's merge rule (`update.merge_new`: backup values, this version's new keys added); config, staging, flow files and processed.txt; CLAUDE.md only if missing or with `--claude-md`; git history from the bundle only into a vault without `.git` (working files untouched). Every replaced file is kept in `system/backups/restore-<time>/`. Never a project file; refused in the development repository.
- **`session.py`**: `backup_today` runs `backup.after_daily_backup` (zip, OneDrive copy, Tidy up, weekly check); the lines go to the status output, and to `backup_notes` in `--json` (so JSON stays clean). `session.py backup` (Health's `offsite` fix) now makes the zip and copies it.
- **doctor / Health**: `offsite_backup` warns from **two days** without a copy (was more than three; its detail still matches the `offsite` fix). New checks `backup_check` (weekly restore check; a warning names the problem and `backup.py check`) and `tidy_up` ("Tidy up, 14-10-2026: removed 23 files, 410 MB"). `health.health()` returns `backups` (those lines when fine); `Health.jsx` shows them under **Backups** with one sentence on what leaves the laptop. Dashboard rebuilt.
- **filechange.py**: undo of a change whose backup Tidy up removed says "the backup of change N has gone … The files log keeps the line."
- **Docs**: `creaite-rules.md` (Non-negotiables: exactly what leaves the vault; folder map: `system/backups/`, `locations`, a new `backup.py` row on its own line; session step 1; Retention), `help.md` (Live server and backups), cx-setup "Restore from a backup zip (BL-323)" (confirmed first), `dev/dashboard-spec.md` (Backups in Health and Settings), the settings catalogue's Essentials line.
