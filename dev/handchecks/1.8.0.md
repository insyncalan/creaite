## Failures

### 2. A reload on Work with a view and a project filter loses the view

- **What happened:** with "All open" (or "Mine") chosen and a project picked (`#work=actions&v=open&p=ORX`, "Status: Open · Project: Orbit Customer App"), a reload came back as `#work=actions&p=ORX&f=none`. The view became "Custom" and its Status (and Owner) filters were gone (02-13). For "Mine" + FAL, the list went from 2 items to 4: closed items and other owners' items were back.
- **What was expected:** "Reload … on Work with a filter … each comes back as it was."
- **Not a 1.8.0 regression.** The 1.7.0 vault does exactly the same (02-13b). It is almost certainly on current main too: `src/core/nav.js` is unchanged from v1.8.0 to main. `restoreNav` applies the view and then the project filter. After that, the address is written without `v=`, so the view is lost on that write.
- **Fine:**
  - A view alone (`v=mine`, `v=soon`) reloads as it was.
  - An open item (`&item=FAL-A-001`) reloads with the item open (02-12).
  - A project page reloads on that project.
  - The board layout survives a reload.
- **Fine, rest of check 2:**
  - Every screen opened with no page errors: Today, Intake, Projects, Work (list and board, an item open), People, a person, Review, Files, Activity, Milestones, Help and all six Settings tabs.
  - Screens were checked in creaite light, Linear dark, Claude light and dark, and Retro Arcade dark.
  - **Close the day's door icon is there at once** after a load or reload on Today (02-18). On 1.7.0 it was empty at `DOMContentLoaded`, `load` and the next frame. On 1.8.0 it has its icon at all three.
  - Diagnostics showed "No errors in the last 7 days" after the walk (02-19) and at the end (99).

### 5. Increase contrast: fails on Alan's Mac, works when emulated

- **Alan:** with macOS Increase contrast on, the dashed copy is still there.
- **This run:** with `prefers-contrast: more` emulated through CDP (`Emulation.setEmulatedMedia`), `.logo .wmd` computes to `display: none` in light and dark. The word and the saffron bar stay. With forced colours the dashed copy also goes (05). The rule is in the served page at line 2286: `@media (prefers-contrast: more){ .logo .wmd{display:none} }`.
- **So the rule itself works.** The gap is between macOS and Chrome: on Alan's machine, Chrome isn't reporting `prefers-contrast: more`. Some possible reasons:
  - the setting was changed after the app window opened, and the window or Chrome wasn't restarted;
  - Chrome on his macOS version doesn't map Increase contrast;
  - the window had an older page loaded.
- **To tell which:** in the creaite window's DevTools console, `matchMedia('(prefers-contrast: more)').matches` with Increase contrast on.
  - If it says `false`, it is the macOS → Chrome mapping.
  - If it says `true` and the dashes still show, it is the page.
- **Moot from v1.9.0:** BL-308 (merged) removes the dashed copy entirely.
