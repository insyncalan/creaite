# Hand checks for creaite 1.9.4

Run these in Chrome as soon as main is green with every v1.9.4 branch merged. Written 14-10-2026 from each item's "### BL-…" write-up in `dev/BACKLOG.md` (on `dev-bl327-defects`, Done when especially), the branch notes `V194-ARCHIVE-NOTE` (`v194-archive`) and `V194-INSTANT-NOTE` (`v194-instant`), and the release-note lines on `v194-fast-save`, `v194-sweep-lock`, `v194-one-server` and `v194-gone-chat`.

**Items (6):** BL-09 (the headline), BL-304, BL-327, BL-328, BL-329, BL-330.

**This replaces** Team 2's BL-09-only draft on `dev-handchecks-19x` (`dev/handchecks/v1.9.4.md`). Its BL-09 checks are kept and corrected to what was built: Archive and Restore live in Settings › People and projects › Projects and register; the folder rename goes on the change card in ask creaite; Show archived is one switch (`dashboard.show_archived`).

**Sample data only.** The fictional demo portfolio (FAL Falcon Data Platform, ORX Orbit Customer App, MER Meridian Contact Centre AI, TID Tide Billing Migration) and its people. **Never Microsoft 365:** OneDrive is stood in for by a local folder, and Claude by a stand-in. Checks marked **live only** need the live vault; run them there after the scratch-vault checks, or skip them.

## Setup

Run on a scratch vault: never the live vault, and never the development repository itself.

1. **Main.** In a clean checkout of `origin/main`: `VERSION` says 1.9.4, and `git log --oneline origin/main` shows the six branches above merged.
2. **The zip and two vaults** (from the repository root):
   ```
   HC=$(mktemp -d -t creaite-hc)
   python3 dev/tools/build_release.py --out "$HC/zip"
   python3 -I system/scripts/update.py new-vault "$HC"/zip/creaite-*.zip "$HC/vaultA"
   python3 -I system/scripts/update.py new-vault "$HC"/zip/creaite-*.zip "$HC/vaultB" --projects "$HC/Engagements"
   ```
   Vault A keeps its projects in its own `projects/`; vault B's are in the stand-in OneDrive, `$HC/Engagements`. In vault B, make `$HC/Engagements/_Templates/_Skeleton/zz Archive/` (empty).
3. **In each vault:** `touch .creaite-dev` (keeps the VIP check and the session-start sweep off), `mkdir -p dev/tools && cp <repo>/dev/tools/demo_data.py dev/tools/`, then `python3 dev/tools/demo_data.py load`. Add FAL, ORX, MER and TID to `projects/_portfolio/project-register.md` and their owners to `people-register.md`. In vault B, also make a `zz Archive` folder inside the ORX engagement folder.
4. **A 1.9.3 vault for the update check:** build the 1.9.3 zip from `git worktree add "$HC/v193" v1.9.3` (or use `system/releases/creaite-1.9.3.zip`), make `$HC/vault193` from it, and set its `locations.never_index` to `["zz Archive", "_Templates", "99 System", "Old stuff"]`.
5. **Stand-in Claude:** from the repository root, `python3 -c "import sys,pathlib,types; sys.path.insert(0,'dev/tests'); import drafts_fake; print(drafts_fake.install(types.SimpleNamespace(root=pathlib.Path('$HC'))))"` writes `$HC/fake_claude.py`.
6. **Start one vault at a time:** in its folder, `CREAITE_PORT=8990 CREAITE_CLAUDE="$HC/fake_claude.py" system/scripts/run live_server.py`. Open the printed address in Chrome. Ctrl+C stops it.
7. **Reset:** Ctrl+C, `rm -rf "$HC"`, then steps 2 to 6. A single change: Undo, or `system/scripts/run tracker.py undo`.

Chrome: DevTools › Network (with "Disable cache") and › Rendering for dark; Device toolbar at 320 px. Run on a weekday: the sample dates follow today.

## Checks

### Start-up

1. In vault A, `system/scripts/run doctor.py` → every check passes, and the list includes the two archive checks (zz Archive folders, the skeleton) and **Sweep lock**. In vault B → the two archive checks warn (the ORX `zz Archive` and the skeleton's); everything else passes.
2. Visit every screen once → no page errors. Settings › Diagnostics says "No errors in the last 7 days" (check again at the end).

### BL-09 Archive a project (vault A)

3. Settings › People and projects › Projects and register → each project has **Archive** beside Close. Press Archive on TID → a dialog lists TID's open items and offers **Cancel them all and archive** or **Stop**. Stop → nothing changes.
4. Archive TID again, then **Cancel them all and archive** → the change card opens in ask creaite, showing the cancellations ("Cancelled to archive the project"), "Move folder projects/TID … → projects/_Archive/TID …" and the register row. Nothing has changed yet.
5. Approve → `projects/_Archive/TID <Name>/` exists and `projects/TID <Name>/` is gone. Nothing is deleted. In `project-register.md` TID's row is under Retired codes as `| TID | Tide Billing Migration | DD-MM-YYYY (archived) |`.
6. Today, Work, Portfolio, Projects, the reminders and `tracker-view.xlsx` → no TID project or items.
7. Search for words from a TID action → found, marked Archived. Open it → it says it is archived. Open its source link → it still opens (the path resolves into `_Archive/`).
8. Turn on Show archived (Settings › Work and views) → TID's items are back in Work, and in the Excel export after the next apply. Turn it off again.
9. In Claude Code, say "add an action for TID to check the invoices" → refused: "archived: restore it first". Say "add project TID" → refused: an archived code is never reused.
10. Stage a sweep file with `[TID]` in a subject (`system/scripts/run sweep.py stage <file>`) → it isn't matched to TID.
11. Activity › the apply → the folder move is listed. Undo → the folder, the register row and the items (still open, not cancelled) are all back exactly.

### BL-09 Restore

12. Archive TID again. Settings › Projects and register, Show archived projects on → TID is listed with **Restore**. Restore → the change card; Approve → the folder is back, the row is in Projects in code order, and the items show in Work and Today (the cancelled ones stay cancelled).
13. Archive TID, then make an empty folder with TID's folder name in `projects/`, then Restore → the restored folder gets a number, and the register's folder cell names it. Nothing is overwritten.
14. In Claude Code, "archive project TID" and "restore project TID" (cx-edit) → each is shown first, confirmed, then applied, as from the dashboard.
15. Compare a fresh archive then restore with the start (folder listing, `project-register.md`, Work's count, a search) → the same.

### BL-09 The guard

16. `system/scripts/run reach.py never` → `_Archive` is on the never list.
17. With TID archived, in ask creaite ask "read the minutes in projects/_Archive" → refused. Ask "move TID's folder back to projects" → refused. Only Restore moves it.
18. Search and Files (documents shown) → nothing from inside `_Archive/` is listed or found.

### BL-09 zz Archive renamed _Archive (vault B)

19. Archive ORX in vault B → its engagement folder moves to `$HC/Engagements/_Archive/<folder>`. Restore it.
20. Search and Files → the ORX engagement's own `zz Archive` folder is still skipped (for this release only).
21. Settings › Health → a line names that `zz Archive` folder, with **Fix it**. Fix it → the change card in ask creaite ("Move folder … zz Archive/ → … _Archive/"). Approve → the folder is now `_Archive`, and Check again clears the line.
22. Health → a line says the skeleton (`_Templates/_Skeleton`) still holds a `zz Archive`, with no Fix it: rename it in Finder. creaite writes nothing in `_Templates`.
23. Before renaming it, add a new project (Settings › Projects, Add project) → its folder has `_Archive`, never `zz Archive`. Then rename the skeleton's folder in Finder and Check again → the line goes.

### BL-09 The update renames the saved setting

24. Install the 1.9.4 zip into the 1.9.3 vault (`system/scripts/run update.py inspect <zip>`, then `install`) → the preview says it changes one saved value. After it, `locations.never_index` is `["_Archive", "_Templates", "99 System", "Old stuff"]`, every other value unchanged, and `settings-log.jsonl` has the old value. Run the install's tidy again → no second change.

### BL-304 Changes appear at once

25. Work, change an action's owner in its cell → it shows at once, with a hollow dot while it saves; the dot clears in about a second.
26. The same for the board (drag a card to another column), the right-click menu (Priority), the peek (a staged change shows its dot) and ⌘K ("mark FAL-A-001 done") → each shows on screen at once.
27. Network tab, filter `api/` → a single change makes a call to `/api/records?ids=…`, never `/api/data`.
28. Settings, auto-apply off → an edit shows with the staged dot until Apply. Turn auto-apply back on.
29. **A refused save:** open FAL-A-002 in the peek in two windows. In window 1 change its due date; in window 2, before reloading, change its owner → window 2's change is put back with "Not saved: … changed elsewhere" and **Retry**. Retry → applied, keeping window 2's owner.
30. Edit an item, then press Undo straight away (while the dot shows) → it goes back, and Activity shows nothing left applied.
31. With Work open, in Claude Code say "mark ORX-A-001 done" and apply → Work updates that row within a few seconds, with no full reload: scroll position, focus and text being typed in a field are kept.
32. Settings › Diagnostics › Reload all data → a full reload (one `/api/data` call).

### BL-327 Slow saves and the first load

33. In vault B, change a document in an engagement folder (any `.docx` or `.md` under a FAL folder), then make an edit in Work → it saves in about 1 to 2 s (Network: `/api/apply` under 2 s). Search for a word you added to the document → found within a few seconds.
34. `system/logs/debug-<today>.log` → the apply's steps each have a time: OneDrive copy, search index, dashboard, Excel. The index line says how many files it read again (only the changed one, not all).
35. Stop and start the server, then open the dashboard with the Network tab open → the page's first document load is under 2 s. Health and Files fill in just after.
36. **Live only:** on the live vault, after a normal working hour, the debug log has no apply over 3 s.

### BL-328 The sweep lock

37. **A lock left by an ended run:** with the server stopped, write `system/staging/sweep.lock` as two lines: today's date and time (`YYYY-MM-DD HH:MM`), then `run hc-ended-run`. Start the server → Settings › Health shows "a sweep lock is held … with no sweep running", with **Release**. `doctor.py`'s Sweep lock check says the same.
38. Press Release → the line goes, and the lock file is gone. Debug log: "an idle sweep lock was released" at INFO.
39. Write the same lock again, then run `system/scripts/run sweep.py lock` in Terminal → "A sweep lock was left by a sweep that has ended; continuing." It takes the lock at once, not after 30 minutes. `sweep.py unlock` to clear it.
40. **A lock still in use:** `sweep.py lock` in Terminal (a fresh lock, no run) → Health shows no Release line while it is under 30 minutes old; a second `sweep.py lock` is refused ("Another sweep started 0 minutes ago"). `sweep.py unlock`.
41. **Live only:** start a sweep from the dashboard, press Stop → no `sweep.lock` is left. Start one, then Ctrl+C the server while it runs → no lock is left after the server stops.

### BL-329 Two servers at once

42. With no server running, run the launcher twice in quick succession (`system/scripts/run launch.py & sleep 1; system/scripts/run launch.py`) → the first says "Starting the live server", the second "The live server is starting on port …; waiting for it…". One server (`lsof -i :<port>`), one Chrome window.
43. With a server running, start a second by hand (`system/scripts/run live_server.py`) → it says "already running" and exits 0 (`echo $?`). The debug log has "already running on port …" at INFO and no "exit 1".
44. While starting, `system/staging/live-server-starting.json` exists; once the dashboard answers, it is gone.

### BL-330 A remembered chat that's gone

45. Open ask creaite, send one message (the stand-in answers), close the panel. Stop the server, delete that chat's file from `system/staging/ask/`, start the server and reload → ask creaite opens a new chat with no error. Reload again → no second `POST /api/chat` 404 in the Network tab.
46. The debug log → one `POST /api/chat 404` at INFO, no WARN.
47. With vault A and vault B open on the same port one after the other, start a chat in each → each vault reopens its own chat; neither asks for the other's. DevTools › Application › Local storage → the key is `creaite-ask-chat:<fingerprint>`, never a path.

### Across the screens

48. Dark mode and 320 px: Settings › Projects and register with Show archived projects, the open-items dialog, the Archived mark in search, the saving dot and "Not saved" with Retry, Health's Release and Fix it lines → readable, with no sideways scroll. Help says what Archive, Restore and Release do.
