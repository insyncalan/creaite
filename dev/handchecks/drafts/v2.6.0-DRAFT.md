## Intake (#232, Team Cap)
1. The rail entry and the page are both called Intake, with the inbox icon and one badge (meetings ready to process plus proposals to approve); the old Intake and Review addresses open the page.
2. The three stage boxes (Arrived, Drafted, Approved) each have an icon and a count and are clickable; Show all is a fourth box with the total; there is no instructional banner.
3. List, Board and Two panes all work; the choice is remembered per person; List is the default.
4. **Add files** is an icon button in the toolbar of all three views and opens the file picker; dropping files anywhere on the page shows "Drop to add files" and adds them.
5. A file you add is a row in Arrived with a file icon and a likely project; Process, Later and Not needed work on it.
6. A transcript (a .vtt, or "transcript" in the name) says it will be turned into minutes and shows **Make minutes**; processing it drafts minutes and proposals for Review.
7. Minutes from someone else ("minutes" or "notes" in the name) say no new minutes are drafted and show **Find work items**; processing gives proposals only.
8. A file it cannot tell shows Transcript and Minutes buttons, is left out of Process all ready until chosen, and the type can be flipped on any row.
9. A refresh icon beside the counts re-reads the calendar and shows "Calendar read hh:mm".
10. Open a mail or Teams proposal that changes an existing work item: the peek shows the whole item (title, ID, Status, Owner, Due, Priority, Project, Workstream, Milestone, Client-visible, latest update with its time, recent activity), and each changed field shows was → now, highlighted.
11. A proposal that changes the latest update shows the old text struck through, the new text highlighted, and an "If approved" line at the top of the activity; the "What changes if you approve" note says it in words.
12. Everything from the 2.5.0 sheet for the combined page still holds (stages, meeting rows, opening a meeting in place, Needs your decision and Routine groups, Approve routine never covering the first group).

## Work items (#241, Team Stark)
13. Status and priority are marks in the list (words in the tooltip and for screen readers); Status and Priority are still available as columns in Display.
14. The default row is a single line with the ID beside the title; Comfortable (today's two lines) is one icon beside the list and board icons; the choice is remembered.
15. Actions are grouped Overdue, This week, Next week, Later, No date, with Closed folded; RAID by priority; Decisions Pending then Made; an explicit "no grouping" you chose earlier is kept.
16. The owner and ID keep their underlines; the owner opens their page, the ID opens the peek; right-click, the Menu key and Shift+F10 open the context menu with Draft email and Chase.
17. Up and Down move; Right or Enter opens the peek; Left closes it, or opens the context menu when no peek is open; a click outside the peek closes it; while it is open, a single click on another row swaps it; double-click opens it.
18. S, O, P and T open the status, owner, priority and due date pickers on the cursor row; C closes with an Undo; V toggles Client-visible.
19. In today's peek, the eye in the bar turns Client-visible on or off in one click (tinted when on), with a badge beside the ID, a Client tag in the list, and Undo.
20. (**Struck if the change history moves to 2.6.1**, as Jarvis's 20-10 note says it may.) The peek's Activity is a complete history: change a field through the peek, a cell, the bulk bar, the context menu and Review, and each shows one event with who, via where, before and after; an undo strikes the original event through and adds its own.
21. The Filter panel and the five quick filters work as today (Find a field, is / is not, counts, Result, Clear all, Done).
22. The tags in a row (Raised again, Client, workstream) sit level on one line.
23. Compact rows are about 40 px high and Comfortable about 57 px.
24. With saved column widths, order and visibility, grouping, board collapse and saved views set, run the update and reload: every one comes back unchanged.
25. A board resize and a column collapse survive an update.
26. Resize a list column (mouse and keyboard), reload: the width is kept; double-click puts it back.
