## Checks

1. **A meeting processed from a file leaves Arrived.** With a calendar meeting today that has an event ID, drop in or upload its transcript in Intake and press Process. Intake shows one row for the meeting: Drafted while the minutes wait in Review, then Done once they are filed. The calendar row no longer stays in Arrived as "Transcript ready". Repeat for a meeting earlier in the week.
2. **Two meetings with the same title on one day.** Make two calendar meetings on the same day with the same title, and process a transcript file for one of them. Both calendar rows stay as they were, and the file's own row is listed. Judgement: does Intake read plainly, with nothing that looks like a lost meeting?
3. **Someone else's minutes.** With minutes from another person for the same meeting waiting in Review (or applied), the calendar row is not linked to them and stays as it was.
4. **Nothing else changed.** Process a calendar meeting with Process from its own row, set one aside with Not needed, and open Review: each behaves as in 2.6.10.

## Not in 2.6.11

- Linking a file processed under another title or another day (a late-evening meeting whose transcript is dated the next day): it stays in Arrived, as before (stated limit in `dev/proposals/389/README.md`).
- Rejected minutes with the transcript filed still mark the meeting processed, as they always have under the meeting's own key.
- No guarded file changes and there is no guarded chain in 2.6.11.
