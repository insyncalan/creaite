## The defect (F5)

`bash_problem` finishes with `_settings_refused(script, cmd.split())`. `cmd.split()` knows nothing about quotes, so the rule "ask creaite never runs `propose.py setting`" (and `workstreams retire-settings`, which clears settings.json lists through the same `cmd_setting`) is compared with the text as typed, not with the words the shell hands to `propose.py`. `'setting'`, `"setting"`, `se""tting`, `s'et'ting` and `workstreams "retire-settings"` are all the word `setting` / `retire-settings` to the shell and to `propose.py`, and all passed.

Only a **confirmed** run was open: in ask, sweep, prep and held the record gate (`record_problem` / `held_kind_reason`, which read the command with `shlex`) refuses `setting` anyway (kind record). So the hole is: Alan presses Go ahead on one thing, and the model then changes settings.json without the approval card, with a backup and a log line but no card. (The third form in the issue, `propose.py workstreams "retire-settings"`, is not another subcommand: it is `workstreams` + `retire-settings`, the same command in quotes. The real rule must refuse it, and does after the fix.)

## The diff: two hunks, 17 lines added, 3 removed

| Hunk | Where | What it does |
|------|-------|--------------|
| 1 | `bash_problem`, last line (~801) | Passes `_unquoted_words(cmd)` instead of `cmd.split()` to `_settings_refused`. |
| 2 | after `_shell_refused`, `_settings_refused` (~836) | Adds `_unquoted_words` (`shlex.split`, `None` if it can't split) and rewrites `_settings_refused` to compare the unquoted words: `setting` as the first argument of `propose.py` (what `propose.py main()` dispatches on: `argv[0]`), `retire-settings` in any place (as before). A command that can't be split is refused (fail closed). The refusal text is unchanged, so the pinned decisions (`dev/tests/pinned/guard/decisions.json`) stay byte for byte the same. |

Why it is safe: `_settings_refused` runs only after `_script_refused` and `_shell_refused`. By then no backslash is allowed outside single quotes or inside double quotes, no `$` or back-quote outside single quotes, and the quotes are balanced, so `shlex.split` reads the quotes exactly as the shell does (the same reading `bash_args`, `record_problem` and the held checks already use). `shlex` also splits on `\r`, which the shell doesn't, but `\r` is in `SHELL_OUT` and refused before. The change can only refuse more, never less: every command the old rule refused is refused (the unquoted words equal the split words when there are no quotes), and the only new refusals are commands whose quoted words spell `setting` or `retire-settings`. `_unquoted_words(...)[2:]` are the script's own arguments for both launchers (`python3 system/scripts/x.py` and `system/scripts/run x.py` have two leading words).

Modes affected: the check is `bash_problem`, which every mode calls first (`bash_refusal` -> `hook_decision` for ask, confirmed and sweep; `prep_decision` for prep and held). Confirmed gains the refusal that matters; the other four already refused and now refuse earlier, with the settings reason. No other function, rule, list or text changes. `creaite-rules.md` already says this ("never `permissions.py` or `propose.py setting`"); the code now matches it, so the rules file needs no change.

What stays refused: everything refused before (plain `setting`, `retire-settings` anywhere, `permissions.py`, `live_server.py`, `launch.py`, any shell character, env prefix, `./`, another folder's path, `sh -c`, `python3 -c`, the hand-over commands, the record gate in a plain chat). What stays allowed: every other creaite script run. `propose.py learn ABC alias setting`, `workstreams add ABC setting` (a name that is the word) stay allowed; `workstreams add ABC retire-settings` stays refused (as before: any position).
