# creaite 1.3.0 (Beta)

The third update. Three things matter most: **Work is far quicker to use** (click to select, edit a value in the table, change several items at once, a Display menu with grouping and swimlanes, better filters and saved views, and an All items tab), **Review triages in bulk** (one selection, mass change before approval, reasons when you reject, and possible duplicates flagged), and **ask creaite can act as the administrator**: it reads and writes widely, but every sensitive change waits on one card you approve, enforced in code it cannot change. Settings is now one page with categories and search, the meeting prep page shows only what needs attention, and the dashboard moves, gently (Settings › Appearance › Motion; it follows your Mac's Reduce motion).

**Still a Beta:** built and tested on sample data overnight on 10-10-2026, with every sprint's tests and one full suite run on the final build. None of it has run on your real vault yet (see "Check once by hand").

## Fixed

- **A number is never used twice in a project.** Actions, risks and issues, decisions and promises now share one number sequence per project, so ABC-A-012, ABC-012 and ABC-D-012 can no longer all exist. Existing IDs are unchanged; new ones continue from the highest number in the project, so each list may skip numbers.
- **An item ID in Activity opens the item, not Today** (BL-144). Clicking a work item, decision or milestone ID opens its side panel and leaves you on Activity; ⌘-click opens it in a new tab. The same fix stops any other item link of this kind jumping to Today.
- **Setting a date on the project page's No due date card happens on the row.** Pick from the calendar, or type DD-MM-YYYY and press Enter, and it saves with the usual checks and Undo; the item then leaves the card. It no longer opens the side panel.
- **Quick Capture's project list is always filled.** It could be empty until the form was opened a second time, and after a data reload it could miss a new project. It is now filled when the page loads, when the form opens and after every reload, and a click on the note reopens the form after **Clear**.
- **The tests no longer open Word** (BL-171). A test run could start Microsoft Word on a throwaway draft and show "user does not have access privileges". The tests now run with `CREAITE_NO_LAUNCH` set, so the live server reports what would open and launches nothing; your own "Open draft" is unchanged.
- **An update now finishes its own clean-ups.** An update is run by the version already installed, so changes a newer version makes to your settings and rules were missed: 1.2.0 never moved the backup copy to `_Portfolio/99 System/creaite backups` or removed its two retired deny rules. From 1.3.0 the new version applies them itself after installing (logged in the settings log, undone by Undo update), so this update also catches up on what 1.2.0 missed. Your own settings and rules are kept.
- **A change already made no longer blocks the apply.** Two proposals that write the same change to one file (for example two memory changes made from the same text) used to stop the whole apply on the second: it found the file already said what it proposed. A write whose target already holds the proposed text, and a copy whose destination already holds the same file, now pass quietly with nothing to undo. A real conflict (the file changed to something else, or a different file is already there) still stops the apply with its message. The same check at preview time no longer calls a file that is already as proposed "changed since".
- **Two edits staged in the same second no longer overwrite each other.** `propose.py stage` named the file to the second, so the second proposal silently replaced the first. A repeat now gets a number (`proposed-…-2-edit.json`).
- **A permission rule is not listed twice.** A confirmed permission-file edit that adds a rule the file already lists keeps one copy and says so ("… is already listed"). Duplicates already in a file are left as they are.

- **ask creaite's request for an already-allowed script no longer dead-ends** (BL-140). A rule asked for in the old form `Bash(python3 system/scripts/propose.py:*)` is read as `…propose.py *`: it is either added in that form or shown as already allowed, with what was actually refused (a `cd … &&` prefix, a pipe, a redirect or a heredoc) and **Try again**. The reasons say what is true, and only a rule that would run anything or reach the database, the engine or the permissions mentions editing `.claude/settings.json` in Terminal. Engine change: `permissions.py`, `live_server.py`, the cx-setup and cx-edit skills.
- **One stale register edit no longer blocks every save** (BL-170). Two changes to the people register made before the first was applied each started from the file on disk, so the second overwrote the first and then failed with "changed since this proposal was made", and every later save failed the same way. The dashboard now builds an edit on the one still waiting, and apply checks every file write before it backs up or changes anything: a stale one stops the apply and names its proposal.

## Changed

- **Staging commands clear their own input files.** The sweep, the calendar refresh and cx-edit used to leave the file they read behind in `system/staging/drafts/`, where draft minutes also live, because Claude cannot run `rm`. Now each command deletes its input itself once its output is written and checked: `sweep.py stage`, `calendar`, `ignore` and `vip record`; `propose.py stage` (`preview` keeps its spec); `minutes.py stage`; `report.py adhoc`, `weekly-stage`, `client-stage` and `steerco-stage`; `prep_page.py build`; and `docx_tools.py fill`. A failed or refused stage keeps its input so it can be fixed and retried. Only the exact `.json` file passed in is removed, and only directly inside `drafts/` (a `..` path, a symlink, a folder or a Word draft is never touched). It prints `Removed draft input: <name>`. The skills no longer tell Claude to delete these files.
- **Update:** removes the two interim rules `Bash(rm system/staging/drafts/sweep.json)` and `Bash(rm system/staging/drafts/calendar.json)` from `.claude/settings.json` if the vault has them (exactly those; any other `rm` rule of your own stays). The release's own settings never carried them.
- **Word drafts are approved without any sensitivity label.** Approving minutes, a report or a one-pager no longer looks for a Word label: the "not yet labelled" refusal, `review.py approve --unlabelled` (now refused with a message), the dashboard's **I've saved it in Word: try again** and **Approve without the label** buttons, and the setting `documents.require_sensitivity_label` are gone. A draft open in Word is still refused, and the other approval checks are unchanged. The update removes the setting from your `settings.json` (logged in the settings log; any other key you keep in that section stays). A label a draft happens to carry is still kept when it is cleaned.
- **What ask creaite may touch is decided in one place** (BL-141). A new engine file, `system/scripts/reach.py`, sorts every path it is asked about into ordinary (done at once, backed up, undoable), sensitive (only on your approval) or never. Its reach is the vault, the projects folder and your home folder; the never list keeps out secrets (`~/.ssh`, `~/.aws`, keychains, password stores, browser profiles and saved logins), the operating system, the files that run commands when you log in, and, for any change, the database, the engine, creaite's rules and its own records. Symlinks and `..` are judged by where they really point, and names in another case are the same place.
- **ask creaite reads your whole home folder and changes files itself, with a way back** (BL-141). It may read anything in the vault, the projects folder and your home folder except the never list. It changes files only through `filechange.py`: an ordinary change (a new file, your notes, drafts, project files you named) is made at once, backed up first, logged and undoable; a sensitive one waits for your approval. It has no other way to write: a guard that Claude Code runs before every step refuses a direct edit outside staging and any command that isn't one creaite script on its own, whatever a settings file allows. `propose.py setting` is refused in ask creaite (settings go through the approval card). New: Activity › **What ask creaite changed**, the last seven days with Undo.
- **One approval card for everything sensitive** (BL-141). A change to ask creaite's own permissions or settings, anything outside the vault and the projects folder, a delete or a move, another person's file (a transcript, sent minutes or a report, a client's document), more than ten files at once, or anything at all after it has read mail, Teams, a transcript, a document or a web page, is listed on one card with the change shown and why it needs you. **Approve** makes all of them, exactly as shown; **Decline** makes none. ask creaite can't approve its own changes: the approval is held by the live server, bound to that exact change, used once and never shown to it. Your permission files are changed directly on approval (no more editing in Terminal), except a rule that would run anything, reach the database, the engine or creaite's rules, skip permissions or remove a safety entry, which is refused whatever is approved. The separate permission cards are gone.
- **The rules, Help and the health check describe the new model** (BL-141). `creaite-rules.md` records Alan's decision (10-10-2026): ask creaite is the administrator, the database and the engine stay behind their own commands, sensitive changes go on one card. `doctor.py` checks that the never list is intact, the permission files are valid JSON, no rule that would reach the database or the engine or run anything has crept into `.claude/settings.json`, no hook switch is set there, and nothing is left over from a run.

- **Rejections can carry a reason** (BL-133 stage B). **Database change, migrated on update:** the `rejected` table gains two optional columns, `reason` and `duplicate_of`; `update.py` runs `tracker.py migrate`, which rebuilds the table keeping every row (a backup is taken first), and `doctor.py` says if it hasn't run. Engine changes: `schema.sql`, `tracker.py` (stores the reason and the duplicate at apply, refuses a duplicate of an item that doesn't exist, `read rejected --project CODE` lists a project's reasons with the items), `review.py` (`reject 4 as a duplicate of ABC-A-009`, `reject 7 because not mine to track`, `--reason`, `--duplicate-of`), `live_server.py` (a reason on a review decision), `build_dashboard.py` (the possible duplicate, reasons in Activity), `doctor.py`, and the cx-review, cx-minutes and cx-sweep skills (the minutes and the sweep read recent reasons as guidance; only the exact item is ever blocked, as before). New settings: `review.duplicate_overlap` (0.6) and `review.auto_advance` (on); `defaults.decisions_view` (all).
- **Review's data has each proposal's age** (`build_dashboard.review_queue`: `age`, `stale`), so the dashboard can tag stale proposals. Engine change: `build_dashboard.py`.

- **Many buttons are now icons with a tooltip; New is a quiet tile; New decision and Decision needed are one button with a menu** (BL-158 to BL-161). Point at an icon, or Tab to it, and its name shows (with its key, if it has one); Help › Reference › What the icons mean lists them all. Actions that start work or decide something keep their word beside the icon (Approve, Approve routine, Weekly report, Draft email, Hand over, Prep page), and Cancel, Save and the like are unchanged. Nothing behaves differently.

## The dashboard

- **The ask creaite message box grows with what you type** (BL-145). A message of several lines, typed or pasted, shows in full up to about half the panel's height, then scrolls inside; the box goes back to one row once the message is sent or cleared.
- **Milestones have a description.** Write what a milestone means or what done looks like in its panel (several lines); it shows in the Excel export and is found by search. Existing milestones start with none. Engine change: the update adds the column, keeping every row.
- **A little motion, and a Motion setting** (BL-136). Buttons press, inputs show a soft ring when focused, the line under a Work tab, the List | Board switch and the Settings categories slide to the one you pick, a highlighted row's tick draws in, the change-several bar rises, one filter chip grows in or closes up, a saved setting shows a spinner and then a tick, copy buttons say **Copied** with a tick (also read out by a screen reader), ask creaite's button catches the light on hover, and changing the theme fades the colours. Menus, dialogs, the details panel and messages ease in; a decided proposal tints; sorting and opening a group glide; dragging a card lifts it; clearing Review draws a tick; rows new since your last visit carry a small dot; figures count up once; a changed value flashes after a refresh; a thin line under the top bar shows a run is going; ask creaite's replies fade in word by word. Nothing loops while you're idle and nothing makes you wait. **Settings › General › Appearance › Motion:** Follow system (default), Reduce or Full. Engine change: `build_dashboard.py` and `settings-defaults.json` (`dashboard.motion`, added by the update with your other settings kept).
- **Current state on the project page:** the **Add notes** link is gone (the pencil opens both panes), and the text keeps the width it has with two panes when the right pane is empty, so it no longer jumps when notes are added or removed.
- **Calendar Import has one Process button.** **Process n selected** loads each ticked meeting's transcript and meeting chat, then runs the minutes on the saved file, one meeting at a time with progress on each row. **Load and process** is gone; **Load into inbox** still loads without processing. A meeting with no transcript to load (No transcript, Not transcribed, No access, or not a Teams meeting) is skipped with the reason on its row, and the others carry on; ask creaite no longer goes looking for a missing transcript in Teams.
- **ask creaite keeps your place.** While a reply is arriving the chat follows it only if you are already at the bottom. Scroll up to read earlier and it stays put; a **↓ New activity** button appears (**↓ Latest · still working** while a run goes) and takes you back, as does scrolling down. Sending a message, opening a chat from History and starting a new chat still go to the bottom. The button is checked for contrast in all five themes.
- **Work shows only the controls for the layout in use.** On the List: Columns and the list's key hint. On the Board: Group by, Sort, Hide empty columns (now on a row of their own, so **New action** no longer jumps) and the board's own key hint. Search, filters, saved views and the applied chips are the same in both.
- **Select and open in the Work lists.** A click on a row now **highlights** it instead of opening it. Open an item by clicking its **ID** (a small link under the title; the ID column too), by double-clicking the row, or with **Enter**. **⌘-click** (Ctrl-click) adds or removes a row, **Shift-click** highlights a range, **Esc** clears the highlight and then closes the details. J and K move a cursor, **Shift** extends, **Space** toggles. The same works on the Board's cards, on a person's page and in Review (where the highlight and the tick boxes are one selection and the bulk rule is unchanged: minutes, reports, health changes, new decisions and new risks are still approved one at a time).
- **Edit in the Work table.** Click a value (or its **▾**) to change it where it is: a list for status, owner, priority, type and workstream, a calendar for a date. A RAID item's priority edits its impact and likelihood. Choosing a value saves it, with Undo in the message; Esc or clicking away leaves it as it was. Free text stays in the details. A double-click on a row now opens its details instead of editing a cell.
- **Change several at once.** Highlight two or more items in Work (list or board) and a bar offers **Close**, **Reopen** and lists for status, owner, due date, priority (impact and likelihood on RAID), workstream and milestone. Each item is checked on its own; any that can't take the change are left out and named, the rest change as one change with one **Undo**. Changing a value in the list on a highlighted row changes it for all of them. Over 25 items asks first.
- **Today's Week ahead no longer lists the weekly and client reports** (BL-127). A report that is due shows once, as the reminder in Needs attention (same wording, Draft button, dismiss and dismiss forever); the Week ahead keeps meetings, actions and RAID items, milestones, Urgent work with no date and Further ahead. It no longer previews a report before it is due.
- **The meeting prep page shows only what needs attention, and reads easily** (BL-126). The work table lists only **Urgent**, **overdue** and **due-soon** items (due soon is Settings › Review's number of days), overdue first, then soonest, then Urgent with no date; a line under it says how many other open items are not listed and links to Work. The reporting block per project has the health as a word and an icon, the headline, the first five key points, the weekly update in a line or two, and the full Current state behind **Show the full current state**. New: **Recent reports**, the latest weekly report, client report and steering one-pager, on the page and in the Prep popup. A report on the saved page opens through the dashboard (the live server must be running). Engine change: `prep_page.py`, `build_dashboard.py`, the cx-prep skill.
- **Files has an Agendas folder** (BL-135). Each project's tree shows **agendas** beside minutes and transcripts, with its own count, whether or not "Show project documents" is on. It lists the prep pages creaite saved and any agenda you keep there (Word, PDF, HTML); a prep page opens in the browser and the others in their own app. Agendas are no longer counted under Documents, so nothing appears twice. They stay passive and internal, and search and ask creaite still read them. Engine change: `paths.py`, `tracker.py` (search stores an agenda as a document), `system/creaite-rules.md`.
- **One Display menu on the Work page** (BL-128). **Display** (or **D**), beside **List | Board**, holds the layout, Group by, Sub-group, Order by with a reverse button, Properties (the List's columns and a card's fields; Milestone and Last updated can now be shown, and Milestone edited in the table) and Show (empty groups; on the Board, the Closed column's window). It replaces Group by, Sort, Hide empty columns and Columns. Reset puts a tab's display back. The key hint under the list is written from the controls that exist.
- **Groups in the List, and swimlanes on the Board** (BL-129). Group the List by project, due, status, owner, milestone, priority, workstream or type: collapsible headers with the count and the overdue count, remembered. One sub-group level: a second header in the List, swimlanes on the Board. A card moved across a lane and a column says both changes first and saves them as one, with one Undo; Move to… offers the lane too. The Board can also group by project, priority, workstream or type, and Decisions by project. A Shift range never reaches a collapsed group; **Select all N matching** says how many are in collapsed groups.
- **Filters: type to find a field, "is not", and new fields** (BL-130). **+ Filter** (or **F**) is a searchable picker. Every field has **is** and **is not** (Owner is not Me); an excluded chip is tinted and says "not". New: **Stale**, **Last updated**, **Raised** (and raised between two dates) and **Milestone** on Actions. Older saved views and links work as before.
- **A useful empty list** (BL-132). When nothing matches, the list names the filters, says how many items removing each one alone would show, and offers **Remove**, **Include closed items** and **Clear all filters**. The count says what is hidden ("Showing 7 of 31 · 14 closed hidden"), and both are announced to screen readers.
- **Saved views you can keep up to date** (BL-131). A changed view shows a dot; **Update view** saves the change into it and **Save as new view** keeps both (a built-in view can only be saved as new). A saved view's ▾ renames it, moves it or deletes it. Views that don't fit sit under **More views**, with the one in use always in sight; Overdue on Actions moves there. New view **Chase** on every tab: open items owned by someone else that have gone quiet. Decisions can now have a default view (Settings › Work and views).
- **Review is a triage queue** (BL-133). Select several (click, ⌘-click, Shift, a group's tick, **Select all**, Cmd/Ctrl+A) and a bar says how many can be approved together and why the rest can't, with **Approve**, **Reject** and **Set** project, owner, due date, workstream or milestone before approving (one Undo; anything refused is named). A batch is written one file at a time and applied once; the result names what was left out, with **Show them** and **Undo** (or Cmd/Ctrl+Z). **Approve all routine** acts on what the filters show and previews first, as does any batch over 25. Search, **Kind**, **Needs**, **Source**, project and age filters (is / is not), **Display** to group by source or kind and order by age, kind or due date, a **Stale** tag, **Open source**, and the cursor moves to the next proposal after a decision (a setting turns it off). An empty queue says what you did. The bulk rule is unchanged.
- **Reject with a reason** (BL-133). The ▾ beside Reject, or **Shift+R**: Duplicate, Not mine to track, Not an action, or Other in your words. A proposal that closely repeats an open item says **Possible duplicate of ABC-A-009**, with **Reject as duplicate** in its panel. Reasons show in Activity. **R** alone still rejects at once.
- **All items: actions, RAID and decisions in one list** (BL-134). A fourth Work tab after Decisions shows everything together, with a **Type** for each (Action, Decision, Risk, Issue, Assumption, Dependency), one Status filter (Open, Closed, Cancelled, each row keeping its own word), the same Display, grouping (by type too), filters, views and saved views as the other tabs, and overdue first. A decision's owner is who made it or is asked, and its due date its Needed by. It is read-only: opening a row opens the item's own details. The project page's Actions card has an **All items** link.
- **People has two tabs** (BL-138). **With work** lists everyone with an open action, an open risk or issue or a decision waiting on them, now with a **Decisions waiting** column; **Nothing assigned** lists the other people creaite knows, with their projects and how many closed items they have. Each tab shows its count, sorts on its own and is kept in the address (`#people/none`).
- **ask creaite's approval card and What ask creaite changed** (BL-141). One card lists every change waiting for you, each tagged **Sensitive** (a word, not only a colour) with why and the change itself, and **Approve** / **Decline**. It comes back if you reload. Activity has a new list below its table: the files ask creaite changed in the last seven days, with **Undo**.
- **Five themes, and creaite is the default** (BL-142). The list is **creaite**, Brightwater, Notion, Linear and Cursor. creaite is what was called creaite teal (with its teal ask creaite button and heading); creaite standard and Minimals are gone. A theme you had saved with one of those names opens as creaite, and the update changes your saved value (logged in the settings log). Pick another in Settings › General › Appearance or with ⌘K › "Theme:".
- **No Live dot in the left bar** (BL-143). The red alert (the restart command and **Check again**) is how you see the live server is down; while it runs there is nothing to see. When mail and Teams were last swept and when the data was built are a line in Settings › System › Live server and backups.
- **Upload Files lists only what you uploaded** (BL-137). A transcript or chat that Calendar Import loaded is no longer listed there at any stage; its state (**Loaded**, **Processing**, **Draft ready**, **Already processed**) is on its meeting row in Calendar Import, which now has **Preview** and, before it is processed, **Remove** for it. The Intake badge still counts a loaded transcript that is waiting.
- **ask creaite's running and finished badge** (BL-139). A small badge at the bottom right of any page shows when ask creaite is working (**ask creaite is working…**, what it is doing, and the time it has taken) and, afterwards, **ask creaite has finished** with how long it took. It follows every run: a chat message, Process selected, a sweep, a report, Generate, the Prep page and a search answer. The finished badge **stays** until you press ×, open the chat or start the next run (it no longer disappears after 15 seconds); a stopped run says **ask creaite was stopped** and a failed one **ask creaite stopped with a problem**. It is hidden while the chat is open. When a run finishes while the tab is hidden, the tab's title gets a ✓ until you look. The dot on the ask creaite button in the top bar stays.
- **Every text box grows with what you type** (BL-146). The edit panel's Action, Latest update and client messaging, Quick Capture's notes, Generate's "Steer it" and the diagnostics report now show what is in them, up to about 60% of the window, then scroll inside; they shrink back as you delete. A box you drag taller stays that tall. The ask creaite box uses the same code.
- **Type dates in plain words** (BL-147). Every date field takes `fri`, `next fri`, `tomorrow`, `+3d`, `+2w`, `next week`, `end of month`, `15-10` or `15 oct` as well as DD-MM-YYYY. It shows what it understood straight away ("Friday 16-10-2026") and then holds DD-MM-YYYY; anything it doesn't understand is said in words, with examples. Quick Capture's date can now be typed too, and ↓ opens the calendar in any date field.
- **ask creaite: copy a reply, recall, edit, try again, and a draft that survives a reload** (BL-148). Every reply has a **Copy** button (on hover or Tab). In an empty box **↑** brings back what you sent (↑ ↓ to move through it). **Edit** on your last message puts it back to change and send again. A stopped or failed run offers **Try again**. A message you haven't sent is still there after a reload (kept in this browser only).
- **ask creaite no longer covers the page** (BL-150). On a window 1100px or wider, opening ask creaite moves the page over to sit beside it, and dragging the panel's edge moves the page with it. With a panel open, Work's filter bar keeps to one row: filters you aren't using fold into **+ Filter** when there isn't room. On a narrower window the panel still opens over the page.
- **Today without a calendar is one quiet line** (BL-151): "No calendar yet" with **Refresh calendar** beside it, in place of an empty timeline. Once the calendar is read the day band opens as before.
- **The browser tab says where you are** (BL-152): "creaite · Work", "creaite · Example Programme", "creaite · Review (4)" with what waits in Review. The finished-run mark still comes first.
- **Work says why a list opened narrowed** (BL-153). If Settings › Opening views starts a tab on a view other than All open, the list says "Opened on Overdue, as set in Settings" with **Show all open**. A new browser opens Work on All open, as Help says.
- **No more "do it in Claude Code" where the app can do it** (BL-149). A report reminder on Today has its own **Draft weekly report** or **Draft client report** button. In Review, **Approve** on draft minutes approves them there (with the usual checks), and a conflicting change shows the current value beside the proposed one with **Keep current** and **Use this one**. The Claude Code phrase now appears only when the live server isn't running.
- **The edit panel shows what matters** (BL-154). An action opens with Action, Project, Owner, Priority, Due date, Status and Latest update; workstream, dates raised and closed, milestone and client messaging are under **More fields**, which opens by itself when one of them is filled in or needs correcting. RAID items and decisions have their own short lists.
- **A Keys chip instead of the line of key hints** (BL-155). Work and Review have a **Keys** chip at the end of the toolbar that shows the keys for the list. The line of hints under the list stays until you open the chip once; after that it's one tap away. **?** (Help) lists them too.
- **A getting-started checklist, and the launcher first** (BL-156). Until set-up is done, Today starts with five steps (Connect Microsoft 365, Add a project, Add people, Run the first sweep, Open Review), each with a button and ticked as you go; **Dismiss** hides it (Settings › Reminders › Restore brings it back). - **A UX baseline, and what the sweep fixed** (BL-157). Every later sprint is checked against ten plain rules (a text box shows what is typed, dates take words, drafts survive a reload, no dead ends into Claude Code, no panel over the page, empty pages say what to do, the right title, forms show what matters, hints one tap away, and each brief checked in the real app). Fixed on the way: an empty Activity or Projects page now says what to do next, Quick Capture keeps a note you haven't processed across a reload, and Activity no longer tells you to go to Claude Code for an older apply.

## Check once by hand

- **ask creaite's guard (most important):** ask it to read `~/.ssh/config`. It must refuse. That proves the guard hook runs in your Claude Code. Then: create a file in a project's Documents (one card; Approve; Undo it from Activity), edit a project note (no card), and add a rule such as WebSearch to `.claude/settings.json` (a card showing the change; Approve; Undo).
- **Work:** walk Actions, RAID, Decisions and All items in List and Board, with the Display menu, a grouping, a filter with "is not", and a saved view. Highlight three items and close them with one click, then Undo. Drag a card on a real board.
- **Review:** select several proposals, change their owner before approval, reject one with a reason.
- **Settings:** find a setting with the search box; check the Advanced section.
- **Meeting prep:** make a prep page for a real meeting, read it, and open each report link (live server running).
- **People:** both tabs list the people you expect.
