# creaite 2.0.2

A security patch to the check that decides which commands ask creaite and the runs creaite starts may run. It closes a way a command could hide a second command from the check.

## Before you update

- **No schema change and no migration.**
- **No new setting.** Nothing is added or moved; every saved value is kept.
- **It replaces the engine only.**
- **A full release**, not a pre-release, so "update creaite" finds it with no version named. To install, say "update creaite".

## Changes

- **The shell-character check no longer misreads an escaped backslash before a closing quote.** A command written as `doctor.py "a\\" ; rm …` looked like one quoted word to the check, while the shell would have run the second command after the `;`. A backslash inside double quotes is now refused, so the check and the shell agree on where a quote ends. Single quotes keep backslashes as plain text, and a backslash outside quotes was already refused. The flaw has been in every version since 1.9.3; Claude Code's own permission rules were not tested against it.
- **Four skills (cx-minutes, cx-steerco, cx-weekly-report, cx-client-report) show the search summary step in single quotes**, because a backslash inside double quotes would now be refused. A summary written there must not contain an apostrophe; if it does, the check refuses the command and ask creaite retries.

## Known, for later

These are being fixed for 2.1.0:

- Held-run commands, ask creaite's chat commands and the newer built-in tools are still being tightened (the same checks as 2.0.1's notes).
