# creaite 1.9.1

A small update for ask creaite and Today. ask creaite now checks every work item it names against the tracker before you see the reply, says plainly "I can't" when something is outside its reach, and makes a field change through the dashboard's own save, with the same card, rules and Undo. And Today's ‹ › day arrows stay in exactly the same place on every day.

## Before you update

- **A full release**, not a pre-release, so "update creaite" finds it with no version named.
- **Nothing to set.** No new settings, no schema change, no migration.
- **The health check still has 30 checks**, as in 1.9.0.
- **ask creaite has one new kind of card.** A change to fields of existing items (owner, due date, status and the like) now shows a card with the change as the tracker would make it; **Go ahead** saves it as an edit in Work would, **Cancel** writes nothing. Larger changes (new items, projects, memory, the register) keep the change card you know.
- **What ask creaite may do is unchanged.** BL-141's guard, the hook and BL-267's record gate are as they were; the model gains no new command (BL-314's guard decision, Alan, 14-10-2026). The new checks only change the words shown and where a button goes.
- **To install:** say "update creaite". With `gh` signed in, creaite fetches the zip itself; without it, download the zip into `system/releases/` first.

## Changes

### ask creaite

- **What it says is checked against the tracker** (BL-314): before a reply is shown, the live server finds every work-item ID in it (`ABC-A-001`, RAID, decisions, milestones, promises) and looks each up. A title beside an ID that is clearly different is flagged "(⚠ doesn't match the tracker: <real title>)"; a wrong owner is corrected inline ("Sara Khan (corrected from the tracker: the reply said Omar)"); an ID that doesn't exist is marked "(⚠ not in the tracker)". A quiet line under the reply says what was checked ("Checked against the tracker: 1 title didn't match."). A shortened or paraphrased title passes. Code blocks are left alone, and if the check fails for any reason the reply shows unchanged. It would have caught 12-10's "FAL-A-007 · Set up weekly cadence".
- **A plain "I can't", first** (BL-314): for what the panel can never do, whatever you confirm (sending, forwarding or replying to mail; posting in Teams; invites; changes in SharePoint or OneDrive; starting or stopping the live server, the app or the login agent), ask creaite says so before offering, never Go ahead then a refusal. One sentence and a button to where it can be done: **Draft email to <name>** (in chase mode when you asked for a chase or a nudge; Open People when the person isn't in the register), or Open Today, Files or Settings.
- **Changes go through the dashboard's own actions** (BL-314): asked to change fields of existing actions, RAID items or decisions (up to ten), ask creaite proposes them; the live server checks each against the tracker and the dashboard's rules (a closed item gets its closed date, a made decision can't go back to pending, a title can't be emptied, owners through the people register, dates and choices normalised) and shows the result as the tracker would write it, never in the model's own words. **Go ahead** is the same save as Work's bulk bar: one change for all the items, applied at once with **Apply edits automatically** on (otherwise it waits for Apply, as any dashboard edit), and one **Undo** for all of it. An unknown ID, a field the item doesn't have or a value it can't take is named on the card, which then offers only **Cancel**. Anything else (new items, projects, memory, the register, client-visible, more than ten changes) keeps the change card you know. The card is not kept over a page reload: nothing is written without it, so ask again.

### Today

- **The day arrows never move** (BL-321): the ‹ and › controls sit at the top right of Today's band, at the same place on every day, whatever the headline, the number of meetings or an all-day line, so you can click through the week without moving the mouse. At the first and last day of the calendar the arrow stays where it is, dimmed and disabled, never removed.

## For developers (not in the app)

- **`claims.py`** (new, library only): the reply check, run on each whole content block before it is emitted, so nothing unchecked reaches the page and an ID is never split. Only ask creaite's chat runs it. The `text` event carries `checked: [{id, kind, said, real}]` only when something changed; the debug log keeps IDs and kinds only. `claims.cant` and `claims.cant_denied` turn a `CONFIRM:` or a refused tool call of the never-possible kinds into a `cant` event.
- **`EDIT: <ID> | <field> | <value>` reply lines** (ASK_PROMPT and CONFIRMED_PROMPT): `build_field_card` checks, normalises and previews them with `propose.py preview`, then sends a `fieldcard` event. Go ahead calls `itemsMove` (the Work bulk bar's save, `batchMove` now a thin wrapper over it): one proposal through `/api/fs`, one apply, one Undo. No new server route.
- **Guard unchanged:** `reach.py`, the hook, `filechange.py`, `permissions.py`, the tool lists and `SCRIPT_COMMANDS` are untouched; `claims.py` has no command line, so BL-267's list needs no entry. `test_guard_pinned`, `test_reach`, `test_record_commands`, `test_script_policy`, `test_run_read_pinned`, `test_ask_access`, `test_ask_confirmed_apply`, `test_ask_change_card` and `test_admin_card` pass unchanged.
- **No new server route.** The field card needs none: Go ahead is the page's own save through `/api/fs` and `/api/apply`. A CHANGE spec holding only field updates is not diverted to it (the paused WIP did, which broke BL-258's card); field changes reach the field card only through EDIT lines.
- **Tests:** `test_ask_claims.py` (19, quick tier), `test_ask_field_card.py` (10: the server's preview, problems and notes, the CHANGE card unchanged, no new route; in Chrome, Go ahead writes one proposal, applied, with Undo, Cancel writes nothing, a card with problems offers only Cancel), and `test_today_days_ui` clicking › through every day and checking both arrows' boxes are identical, with reduced motion, with motion and at 320 px.
- **One release branch** (`release-191`, Team 2, `dev/RELEASE-BRANCHES-NOTE.md`): built from `release-190` with `--no-ff` merges of `v191-ask-claims`, `v191-ask-routing` (its one conflict, `ask.js`'s imports, kept both; `dashboard.html` rebuilt with `split_dashboard.py build`, since a text merge of the built page differs from a rebuild) and `fix-day-arrows` (clean; `sprint-today-days-ui`, which it follows, is already in `release-190`). No fixes and no goldens changed. Branch notes: `dev/archive/notes/v1.9.1/V191-ASK-CLAIMS-NOTE.md`, `dev/archive/notes/v1.9.1/V191-ASK-ROUTING-NOTE.md`, `dev/archive/notes/v1.9.1/V191-DAY-ARROWS-NOTE.md`.
