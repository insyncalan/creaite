# creaite 1.9.4

"Archive, and no waiting." A finished project can now be archived whole (its folder, its register row and its items) and brought back exactly. Edits show on screen the moment you make them and save in the background, and saves and the first load no longer wait for the search index or the OneDrive copy. Runs creaite starts itself, such as a Prep page, show in ask creaite as one plain ask, the steps and the outcome. And four smaller fixes: a sweep's lock, two servers at once, and a remembered chat that's gone.

## Before you update

- **A full release**, not a pre-release, so "update creaite" finds it with no version named.
- **A schema change and a migration** (BL-09, Alan's own schema change). Projects and their items gain an `archived` flag. The update runs `tracker.py migrate`, which keeps every row (the backup before it is taken as for every migrate); a second run changes nothing.
- **One saved value changes** (BL-09): `zz Archive` becomes `_Archive` in your `locations.never_index`, in its place; every other value is kept, the old one is in `settings-log.jsonl`, and the update's preview says so. It is the only saved value an update has changed.
- **`zz Archive` becomes `_Archive`.** Folders still called `zz Archive` in your OneDrive keep being skipped for this release, and Settings › Health lists each one with **Fix it** (below). If `_Templates/_Skeleton` holds a `zz Archive`, rename it to `_Archive` yourself in Finder: creaite never writes in `_Templates`.
- **The guard has one agreed exception** (BL-09; Alan, 14-10-2026): `tracker.py apply`, running an approved archive, restore or rename, may move a whole folder into or out of `_Archive`. Nothing else may: `_Archive` stays on ask creaite's never list for reading and writing.
- **The health check has 35 checks** (32 in 1.9.3): the `zz Archive` folders, the skeleton, and the sweep lock.
- **To install:** say "update creaite". With `gh` signed in, creaite fetches the zip itself; without it, download the zip into `system/releases/` first.

## Fixes

- **Archive and restore a whole project (BL-09).** Settings › People and projects › Projects and register lists each project with **Archive** (or **Restore** for an archived one, shown with **Show archived projects** on), or say "archive project ABC" or "restore project ABC". A project with open items lists them first and offers **Cancel them all and archive** or **Stop**; nothing is archived with an item still open. The change goes on the approval card in ask creaite: the folder moves to `_Archive/` (`projects/_Archive/<CODE> <Name>/`, or `_Archive/<engagement folder>` in OneDrive), the register row moves to Retired codes, and the project and its items are marked archived. Nothing is deleted, and Undo in Activity puts it all back.
  - **Gone from the views:** Today, Work, Portfolio, Projects, the reminders, the sweep's matching and the Excel export leave it out. **Show archived projects** (also in Settings › Advanced › Work and views) brings its items back.
  - **Still found:** search finds its items, marked Archived, and every source link still opens. The files in `_Archive/` aren't indexed, and ask creaite can't read them.
  - **Restore** reverses each step. A folder name that's taken gets a number and the register says so; nothing is overwritten. Items cancelled to archive stay cancelled.
  - **Closed for good:** no new item can be added to an archived project ("archived: restore it first"), and an archived code is never reused.
  - **The rename:** Health lists each folder still called `zz Archive` with **Fix it**, which puts the rename on the approval card. A new project made from the skeleton gets `_Archive`, never `zz Archive`.
- **Changes appear at once (BL-304).** An edit in a Work cell, on the board, from the right-click menu, the bulk bar, the peek or ⌘K shows straight away, with a hollow dot on the row while it saves in the background through the same proposal and `tracker.py apply`, so validation, logging and Undo are unchanged. The dot clears once it is applied. With auto-apply off, the change shows with the staged dot until Apply.
  - **Not saved:** if a save is refused, the row is put back with the reason ("Not saved: FAL-A-002 changed elsewhere; reloaded it") and **Retry**. Retry keeps your value, applied on top of the item as it now is (Alan, 15-10-2026); the other change stays in Activity and can be undone.
  - **Undo** works while a change is still saving, as after.
  - **Only what changed is fetched:** a change made elsewhere (Claude Code, another window) updates its rows within a few seconds without a full reload, keeping your scroll position and what you are typing. Settings › Diagnostics › Reload all data still reloads everything.
- **Saves and the first load no longer wait for the slow steps (BL-327).** An apply now answers once the tracker is written and the dashboard rebuilt; the search index and the OneDrive backup copy run straight after, in the background, one at a time, so search can be a few seconds behind. The index reads again only the files that changed (a full rebuild only when its readers change, or with `tracker.py index`). The first page after a start is served from the last built data and the rest follows. The debug log now times each step after an apply (OneDrive copy, search index, dashboard, Excel) and a slow page build's parts. A saved Current state's sentence links (BL-207) count as a change to the page, so the claims under Current state stay after a reload.
- **ask creaite shows the ask, the steps and the outcome of a run creaite started (BL-326).** A Prep page, **Generate** or **Make it executive**, an AI draft (**Draft agenda**, **Shape this meeting**, **Polish** and the rest), a meeting's transcript check or load, and Close the day's catch-up sweep no longer show the instructions creaite gave Claude or Claude's raw reply. Wherever ask creaite shows one, it shows three things: the ask, as one plain line ("Prep page for FAL Steering committee, Thursday 15th October 10:00"); the working line and **✓ n steps**, each step in plain words ("Reading the tracker", "Searching mail"); and one outcome line with a link ("Saved the prep page in Falcon Data Platform › agendas · Open"), or what went wrong and what to do ("Couldn't finish: … Try again"), or that it was stopped. The day's runs are kept in History as one chat, **Runs creaite started, DD-MM-YYYY**, so they never push your own chats out of the ten kept. A chat you type is shown as before.
- **A sweep's lock no longer outlives the sweep (BL-328).** The lock now records the run that holds it, and the live server releases it however the sweep ends (finished, stopped, timed out) and when the server stops. A lock left by a sweep that has ended is replaced by the next sweep at once, rather than refusing it for 30 minutes. Settings › Health (and doctor) shows a lock held with no sweep running, with **Release**; a running sweep keeps its lock.
- **One live server, however quickly creaite is opened twice (BL-329).** A server that is starting leaves a mark until it answers; a second launch waits for it (up to 20 seconds) instead of starting another, and opens no second window. A server that finds this vault's own server already on the port says "already running" and stops cleanly, so the debug log no longer shows "exit 1" for it.
- **A remembered chat that's gone** (BL-330). When ask creaite's remembered chat is no longer in the history (only the 10 most recent are kept) or belongs to another vault, the page forgets it at once and starts a new chat, instead of asking for it again; the debug log notes it at INFO, not as a WARN. The remembered chat is now kept per vault.

## Known, for later

- **BL-09:** both `zz Archive` and `_Archive` are skipped for this release only; after it, only `_Archive` is known.
- **BL-304:** a refresh redraws the current view, not only the changed rows. Today's week ahead and day plan, the early warnings and the meeting hub catch up at the next full reload. Review's Approve and Reject, milestones, workstreams, the register, health and Current state still wait for the save and reload everything, as before.
- **BL-326:** the VIP check isn't a run creaite shows in ask creaite, so nothing changed there.
- **BL-327:** the first page is served from the last built data until a save or a change to its files; a change made to the database outside creaite (never done in normal use) shows only after the next save.
- **BL-328:** a lock taken in Terminal (with no run) is treated as ended only once it is 30 minutes old, as before.

## Check once by hand

1. **After updating:** say "what version is creaite?": 1.9.4. `system/scripts/run doctor.py` runs 35 checks; in OneDrive, any folder still called `zz Archive` is a warning with Fix it in Settings › Health.
2. **An edit:** in Work, change an action's priority: it shows at once with a hollow dot, then "… — saved and applied". Undo.
3. **A Prep page:** Today › a meeting › Prep › **Prep page**, and open ask creaite while it runs: one ask line, the steps, then "Saved the prep page in … · Open".
4. **Archive:** only when a project is truly finished: Settings › People and projects › Projects and register › Archive, then Approve on the card. Undo in Activity if it was a test.

The full hand checks are in `dev/handchecks/v1.9.4.md`.
