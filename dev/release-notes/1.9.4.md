# creaite 1.9.4

## Fixes

- **A sweep's lock no longer outlives the sweep (BL-328).** The lock now records the run that holds it, and the live server releases it however the sweep ends (finished, stopped, timed out) and when the server stops. A lock left by a sweep that has ended is replaced by the next sweep at once, rather than refusing it for 30 minutes. Settings › Health (and doctor) shows a lock held with no sweep running, with **Release**; a running sweep keeps its lock.
- **A remembered chat that's gone** (BL-330). When ask creaite's remembered chat is no longer in the history (only the 10 most recent are kept) or belongs to another vault, the page forgets it at once and starts a new chat, instead of asking for it again; the debug log notes it at INFO, not as a WARN. The remembered chat is now kept per vault.
- **One live server, however quickly creaite is opened twice (BL-329).** A server that is starting leaves a mark until it answers; a second launch waits for it (up to 20 seconds) instead of starting another, and opens no second window. A server that finds this vault's own server already on the port says "already running" and stops cleanly, so the debug log no longer shows "exit 1" for it.
- **Saves and the first load no longer wait for the slow steps** (BL-327). An apply now answers once the tracker is written and the dashboard rebuilt; the search index and the OneDrive backup copy run straight after, in the background, one at a time, so search can be a few seconds behind. The index reads again only the files that changed (a full rebuild only when its readers change, or with `tracker.py index`). The first page after a start is served from the last built data and the rest follows. The debug log now times each step after an apply (OneDrive copy, search index, dashboard, Excel) and a slow page build's parts.
