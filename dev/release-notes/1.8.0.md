# creaite 1.8.0

The eighth update, and the first release out of Beta. The dashboard has been rebuilt underneath: its code is now organised by screen, type-checked and escapes every value by default, while every screen stays exactly as it was, so there is nothing to relearn. Around it: fifteen fixes from the 1.6.1 and 1.7.0 hand checks and the live diagnostics, among them on-track milestones always green, "On track" for clients too, shorter top risks, every AI drafts switch honoured, and an "update creaite" that finds the newest release again.

## Before you update

- **creaite is out of Beta.** 1.8.0 is a full release, not a pre-release, so 1.7.0's "update creaite" finds it with no version named. From 1.8.0 on, "update creaite" would also find a pre-release, if one were ever published (BL-280).
- **Nothing to relearn.** Every screen, text, key and button is where it was. The one thing you may notice is that Close the day's door icon is there straight after a load or reload (before, it stayed empty until Today was drawn again). If anything else looks or behaves differently, it is a fault: **Settings › System › Diagnostics** › Copy diagnostics, and send it.
- **The health check still has 28 checks.**
- **To install:** say "update creaite". With `gh` signed in, creaite fetches the zip itself; without it, download the zip into `system/releases/` first.

## Changes

### ask creaite

- **Undo after approving a change on ask creaite's card leaves nothing in Review** (BL-289): Undo put the change back into Review as pending, so asking for it again gave a card that could only stage it. The card's change was never in Review, so Undo now only reverses it (the item back as it was, the proposal kept in `applied/` and marked undone), and asking again gives the same card, with Approve. A change staged for Review, or approved in Review, still returns to Review on Undo. The approval itself is unchanged: the live server's, used once, bound to the change shown and at most 30 minutes old.
- **A refused `system/scripts/run` command is described properly** (BL-278): a refusal of, say, `system/scripts/run tracker.py read actions > actions.txt` read "I tried to run run, which isn't one of creaite's scripts". It now names the script, as the `python3 system/scripts/…` form always did: "I tried to save the output of the tracker (tracker.py) to a file…". Wording only; the guard is unchanged.

### Review

- **Undoing a project move puts everything back** (BL-281): moving a pending item (or a set of minutes) to another project clears the milestone and workstream that belonged to the old project, and Undo moved it back without them. The move now remembers what it cleared, and moving back to that project, with Undo or by hand, restores them.

### Milestones and the project page

- **On-track milestones are always green** (BL-294): an on-track milestone's dot and label took the theme's accent, so it was teal, blue or purple depending on the palette and could pass for a link. It now uses the status green in every palette, light and dark, and in high contrast; Achieved is still told apart by its ringed tick.
- **On track reads "On track" for clients too** (BL-299): the Client view, the client report and the client-safe steerco one-pager said "On plan" for an on-track milestone. They now say "On track", as the Internal view does. Expected later and Late are unchanged.
- **Top risks and issues show at most five lines each** (BL-300): on a project page, the text under each risk or issue is its latest update, falling back to its response, and a long one is cut at five lines ending in "…", with a quiet More and the full text as a tooltip. The row opens the item in full, by click or by Enter.

### Settings and accessibility

- **Every AI drafts switch is honoured** (BL-290): with a switch off in **Settings › General › AI drafts**, its control is greyed with the reason, never hidden and never live. With Polish off, Draft email keeps the Polish row, its tone chips and button greyed, saying why (before, the row went). With Forms off, Generate's four other forms are greyed with the reason and Generate falls back to Current state (before, they stayed clickable and a remembered one stayed pressed). With Spot repeats off, Review shows no "Looks like" at all (before, the older word-overlap hint still showed). Rejecting as a duplicate is unchanged.
- **Settings switches are read out by their labels** (BL-279): a screen reader named the "Apply edits automatically" switch `autoApply`, and every other Settings switch by its settings key in the same way (`srcInbox`, `dailyBackup`…). Each switch is now named by its row's own label, with the row's hint as its description.
- **Increase contrast drops the wordmark's dashed draft** (BL-291): under macOS's Increase contrast the dashed copy behind the word stayed, recoloured; only Windows contrast themes dropped it. It now goes in both; the word and the saffron bar are unchanged.
- **The panel's Close and the Search button behave like their keys** (BL-231): the item panel's ✕ now does what Cancel and Esc do (it drops an unused draft health reason, moves focus out of the panel and updates the address bar), and a click on Search starts with no earlier "which one?" choice, as ⌘K does.

### Running creaite

- **"update creaite" fetches the newest release again** (BL-280): with no version named, `update.py fetch` failed with "release not found", because every creaite release so far was a pre-release and `gh release download` without a tag skips those. It now lists the releases, picks the highest version (pre-releases included, drafts left out) and downloads that one. Naming a version (`fetch v1.8.0`) works as before.
- **A harmless browser notice is no longer counted as an error** (BL-283): Chrome's "ResizeObserver loop completed with undelivered notifications" (seen on a project page) was logged as `ERROR dashboard`, so Diagnostics, the errors banner and the health check's repeated-errors check reported it. The page no longer sends it, the server drops it (one debug line a day at most), and the text boxes' and ask creaite's resize handlers, which raised it, now refit on the next frame. A real script error is reported as before.
- **A page that reloads mid-reply is no longer logged as a server error** (BL-284): when the page went (a reload) while the server was answering, say, the regular Review-count check (`/api/pulse`), the broken connection was logged as `ERROR server · POST /api/pulse 500`, which Settings › Health then showed. It is now logged at info as "client left", on every route. The check also skips a proposal that vanishes or is caught half-written while it counts, and answers with the rest.
- **The last `python3 system/scripts/…` messages use the wrapper** (BL-282): the login agent's "Remove it any time" line, a new vault's "Start the live server" step and ask creaite's "I'll run it the usual way" after a refused command now say `system/scripts/run …`, as everything else has since BL-237. Both forms still work.
- **The Help guides show the new icon** (BL-277): First Day and How-To now draw Stage in their header, not the old teal c; their own colours are unchanged.
- **Lists and forms in the item peek look only inside themselves** (BL-303): the owner, date and new-workstream popups found their search box, options, error line and fields with a lookup that searched the whole page, so a matching element elsewhere (such as the edit panel's own New workstream box) could be read or focused instead. Each now searches only its own popup. Nothing changes in normal use.
- **An old Settings button no longer fails** (BL-302): the older workstreams list's click handler still had a people branch that called a save step removed with the people register (BL-55), so a people button there would have stopped with a script error. Settings › People has its own buttons; the leftover branch is gone and the workstreams list works as before.

## For developers (not in the app)

- **The dashboard's in-place wrappers are folded** (BL-231 phase 2): the 245 places where a later block replaced an earlier function with one that called it (`const rd=reloadData; reloadData=…`) are gone. Each function now holds all its steps, in its original place and in the order they ran, so what a function does no longer depends on the order of the blocks. `wrappers.py` reports 0 and `check.py`'s baseline has `wrappers: 0`. The screen snapshots are byte for byte as before. The calls the page makes while it loads, before the later blocks used to add their steps, run as they did (a `LOADING` flag and a few ready checks). `dev/archive/notes/v1.8.0/V18-FOLD-NOTE.md` has the details.
- **The dashboard is built from ES modules** (BL-231 phase 3): its source is in `system/templates/dashboard/` (`shell.html`, `style.css` and `src/`, one module per area plus `src/core/`, joined by `src/main.js`), and `python3 dev/tools/split_dashboard.py build` bundles it with the pinned esbuild (0.28.2, hash-checked, development only) into `system/templates/dashboard.html`, still one self-contained page, committed. **Never edit `dashboard.html` itself.** `check.py` fails with `BUILT` when the page is out of date with its source, `build_release.py` refuses a stale page, and JSDUP fails a name declared in two modules. The release zip carries the built page only; a vault never needs esbuild or Node. Step 2a's split was byte for byte; after 2b every screen snapshot is unchanged.
- **The modules are type-checked** (BL-231 phase 4): every module has `// @ts-check`, and `tsc --noEmit` with `checkJs` (`dev/jsconfig.json`, the page's DOM types in `dev/types/page.d.ts`) reports 0 errors, from 806 (243 once the DOM types were in). Comments and types only: no code changed. The count is in `check.py`'s ratchet (`tsc: 0`); without Node on the machine it says "not run". The type check found two latent faults, BL-302 and BL-303.
- **The dashboard escapes by default everywhere** (BL-231 phase 5, the rest of BL-228 part D): every screen now writes its markup through the `html` helper (`putHTML`, `addHTML`, `swapHTML`, and `writeDoc` for the Prep page's window), so each value from the tracker or a file is escaped unless it is page-built markup marked `raw()`. `check.py`'s count of HTML-string sinks fell from 240 to 4, the helpers themselves, and `innerHTML` from 162 to 12. The hostile-text test now also covers Settings' and Help's tabs, the milestones page, Work's and Review's menus, the item panel's pickers and the rail's menu. Every screen snapshot is unchanged.
- **The demo loader runs again** (BL-292): `dev/tools/demo_data.py load` stopped at its Word step, which BL-271 refuses outside `system/staging/drafts/`. It now builds each Word file there and files it into the project folders through the demo's own `tracker.py apply` (copy operations, as cx-minutes files minutes), so `purge`'s undo removes them too. `test_demo_data.py` loads and purges it on a scratch vault.
- **Milestone colours are held by a test** (BL-294): a test flags any milestone state drawn with the accent colour; milestone and health states use only the status colours.
