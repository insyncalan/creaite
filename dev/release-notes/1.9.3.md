# creaite 1.9.3

"Sneak peek and safe backups." With an item open in the peek, type `//` and say what should change ("Sara owns this, due Friday", "push it out a week", "raise a risk that the test dates slip"): the change shows as you type, Enter makes it, Undo takes it back. Backups now look after themselves: one closed daily zip of everything needed to rebuild the vault goes to your OneDrive backup folder, old copies are tidied by an agreed schedule, a weekly check makes sure a restore would work, and Settings › Health can restore from any of them. And search now reads the text of PDFs.

## Before you update

- **A full release**, not a pre-release, so "update creaite" finds it with no version named. No schema change, no migration.
- **What leaves the laptop changes** (BL-323; Alan, 14-10-2026; one of creaite's non-negotiables). Until now the one thing that left the vault was a closed copy of the daily database backup. From 1.9.3, a **closed daily zip of everything needed to rebuild the vault**, `creaite-backup-YYYY-MM-DD.zip`, goes to the same company OneDrive folder, `_Portfolio/99 System/creaite backups/`, which only you can open. It holds:
  - the day's database backup (a closed copy, never the live database);
  - `system/config/` (settings and their logs) and `.claude/settings.local.json`;
  - the root `CLAUDE.md`;
  - `system/staging/` (proposals, drafts, the saved calendar), **except** ask creaite's chats and their images, and `vip.json` (VIP is private to you);
  - the vault's git history as one closed file (a git bundle);
  - the daily trend files (`system/history/flow-*.json`), `processed.txt` and a `manifest.json` (each file's size and checksum, the day and the creaite version).

  **Stays on the laptop:** ask creaite's chats and their images (they can hold mail and Teams text) and `vip.json`, never in a zip; the live database, the git folder and the working files, never synced; the engine and release zips, the search index, the debug log, the full dashboard snapshots and the local undo copies. creaite's rules (Non-negotiables, the folder map, the session start and Retention) say so.
- **Old backups are now removed, automatically** (BL-323). Nothing was ever pruned before. Once a day, after the backup and the zip, **Tidy up** removes old copies creaite made, by the schedule below, without asking. **A tidied backup can't be brought back** (agreed, Alan, 14-10-2026). It removes only files creaite wrote, by their exact name in their own folder, never the newest of each kind, never in the development repository, and nothing on a day the zip failed. **It never runs from an ask creaite run** (Alan, 14-10-2026): only from your own Claude Code session start and the live server's daily job.

  | What | Kept (here and in OneDrive) |
  |---|---|
  | Daily database backups and daily zips | every day for 30 days, then each Monday's for a year, then the first of each month for good |
  | Apply, undo, revert, migrate and restore copies | 14 days |
  | Dashboard snapshots | 30 days, then one a month (the daily trend files for good) |
  | Release zips | the installed one and the two before it |
  | Update backups | the last three |
  | File-change backups | 90 days (undo of an older change then says its backup has gone) |
  | Reports and applied proposals | all |

  The values are in Settings › Advanced (Safety).
- **The old daily `tracker-*.db` copies in OneDrive** age out under the same schedule; no new ones are made. The "latest 14" rule for that folder is retired.
- **The OneDrive folder must be kept on this device**, as for the projects (BL-85): the zip is written under a temporary name and renamed, so OneDrive never syncs half a file. If OneDrive can't be reached, nothing stops, and the copy is made the next day it can be.
- **The search index is rebuilt once** (BL-275), the first time search runs after the update, so the PDFs you already have are read. It may take a little longer that once.
- **The after-update steps** (BL-320). If 1.9.2 is installed, this update remakes the launcher, refreshes the app's icon and restarts the live server by itself, and its summary reports each step. If you are updating from 1.9.1 or earlier, do them by hand this once, in Terminal in the vault folder: `system/scripts/run launch.py make-launcher --if-present`, then `system/scripts/run launch.py refresh-icon`, then **Settings › Health › Stop** and open creaite again from the launcher.
- **The health check has 32 checks** (30 in 1.9.2): BL-323 adds the weekly restore check and Tidy up.
- **To install:** say "update creaite". With `gh` signed in, creaite fetches the zip itself; without it, download the zip into `system/releases/` first.

## Changes

### Sneak peek

- **Change an item in words** (BL-322): with an action, risk, issue, decision or milestone open, press `//` (outside a field), click the sparkle in the peek's top bar (left of Draft chase) or the "// Change this item in words" line at its foot. A small box floats over the bottom of the peek; the item stays in view. One `/` still opens ask creaite, after a third of a second. Esc closes the box only; ↑ in the empty box brings back your last instruction.
- **Plain code first:** owners from the people register (type `@` for a list of people, filtered as you type; two of a name ask which; no match changes nothing), dates in your words ("Friday", "next Tuesday" is next week's, "20-10", "in 3 days", "push it out a week"), status, priority, impact and likelihood (with the priority worked out), workstream, milestone, labels, an update, a risk's response, a decision's revisit date or condition. No model call; the card says "Understood in plain code". What was understood is marked in your words, and a click takes a word back out.
- **Enter makes it**, through the peek's own save and the tracker's own rules (each change is tried in the tracker's dry run first), applied in one step, with **Undo**. The changed fields flash briefly (held still under reduced motion).
- **A confirm for the bigger things** (amber card; ⌘⏎ or a click, never plain Enter): rewording the description or decision, cancel and withdraw, decision made (with its date and who), client-visible on (refused until the client message is complete, with an offer to draft it), removing Sensitive, a milestone's state (with a reason when it's better than the dates suggest), and a risk becoming an issue. Closing or cancelling offers an optional closing update.
- **Tasks from the item:** link it ("blocked by FAL-012"); a follow-on action, a risk raised from an action, or a promise, each linked to this item, with one Undo for both; "chase Tom, firmer" opens Draft chase to that person in that tone (**nothing is sent**); quick facts (last chased, where it came from, what it blocks); go to the source, the milestone or the project.
- **Claude only where code can't:** tidying an update or wording one from your reason, a client message, a decision's reasoning and options, shown beside yours with **Use this** or **Keep mine**; the card says "Read by Claude". With AI drafts off, the plain-code part still works and the Claude parts say why they can't.
- **Never in this box:** the baseline date, the project, ID, source, raised and closed dates, deleting, sending mail or Teams, more than one existing item, health, project details, settings or the people register. A refusal says where it can be done, with a button.
- RAID items, decisions and promises have no latest-update field, so "add an update" on them points to the response instead; a milestone's "because …" goes into its internal note.

### Backups

- **The daily zip** (BL-323): made after the daily backup, in `system/backups/`, and copied to `_Portfolio/99 System/creaite backups/` (contents above). With the projects, memory files and people register already in OneDrive, the zip and a release rebuild the vault.
- **Tidy up** (BL-323): once a day, by the schedule above; each run is logged (counts and sizes only) and Settings › Health shows the last one ("Tidy up, 14-10-2026: removed 23 files, 410 MB").
- **A weekly restore check** (BL-323): opens the newest local backup and the newest zip's database, runs SQLite's integrity check, checks the zip against its manifest and reads the git bundle. A failure is a Health line with what to do, and doctor reports it. The OneDrive copy now warns after two days without one (it was more than three).
- **Restore from a backup** (BL-323; Alan, 14-10-2026): **Settings › Health › Restore from a backup**: Choose a backup… lists the zips by date, Preview shows on a confirm card what would be replaced (nothing changes), and Restore restores. Or say "restore creaite from backup" in Claude Code. A restore keeps a copy of the current database first, merges the settings as an update does, restores staging and the git history, and replaces `CLAUDE.md` only if it is missing (or on a separate yes); every file it replaces is kept beside the backups. It never touches a project file, and it is refused while an ask creaite request is running.

### Search

- **Search reads PDFs** (BL-275): PDFs exported from Word or PowerPoint, which search found by name only, are read with the bundled pypdf 6.19.0 (with typing_extensions 4.15.0 on Python 3.9 and 3.10). A scanned, password-protected or damaged PDF is still found by its name, with a debug line giving only its path. A very long PDF is read up to the usual limit; an online-only OneDrive file is never read.

## Known, for later

- **pypdf 6.19.0, not 6.20.1** (Alan's two-week rule): 6.20.1, with further limits on the work one PDF can cause, is two weeks old on 26-10-2026 and is taken in a release from then on.
- **Missed OneDrive days aren't backfilled:** when OneDrive is back, only the newest zip is copied.
- **Sneak peek:** taking a marked word back out tidies the joining words ("and", commas) as best it can.
