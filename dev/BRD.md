## Purpose and problem

creaite is a personal reporting system that turns meeting minutes, email and Teams traffic into one up-to-date view of a portfolio of fewer than 5 projects.

Today, project status lives across Outlook threads, Teams chats, meeting notes and memory. Actions, decisions and risks are captured inconsistently, and preparing a status update means re-reading sources by hand. The system should make the current position of every project answerable in minutes, not hours.

## Objectives and success measures

Success means every project's weekly report produced in under 30 minutes in total, with no action or decision lost between meetings. A portfolio-level summary is backlog BL-02.

| Objective | Success measure |
| --- | --- |
| Capture every action, decision and risk from meetings | 100% of minutes processed within 1 working day |
| Keep one source of truth per project | Single tracker covers all projects; no side lists |
| Answer ad-hoc questions fast | Any "what did we agree on X?" answered in under 5 minutes |
| Cut status-report effort | All weekly project reports drafted and approved in under 30 minutes |
| Surface problems early | Overdue actions and rising risks flagged every week |

Targets are proposed starting points; adjust after the first month.

## Scope and constraints

The system is for one user, keeps its engine and record on the laptop (and, if the user chooses, the project files in the company OneDrive), and presents it through a local web dashboard.

**In scope**

- Storing meeting minutes and Teams transcripts in a local folder on the laptop, or in the company OneDrive's engagements folder
- Searching Outlook (Inbox, Sent Items), Teams chats and channels, and calendar meetings (transcripts and meeting chat) for portfolio projects
- Extracting actions, decisions, risks, issues and status signals
- A web interface for the portfolio
- Weekly project updates with health status, and on-demand Q&A
- Per-project reports (weekly status and client), generated from the same data; portfolio-level reporting is in the backlog

**Out of scope (for now)**

- Financials, resourcing and timesheets

**Constraints**

- Basic Microsoft 365 only: no Power Automate or Copilot
- Work laptop (macOS primary; Windows supported): no hosting; Claude desktop app and Claude Code command line, Python 3 for small local scripts; a local server on 127.0.0.1 is approved by IT
- Local only: no OneDrive, cloud storage or third-party SaaS for project data

## Solution architecture

Minutes and transcripts live in a local vault; Claude reads them plus mail and Teams; a local SQLite database is the record, an Excel export is the editing surface, and a local HTML dashboard is the web interface.

&#91;embedded content: solution architecture\]

Claude Code in the Claude desktop app is where the system runs: it opens the vault as a project, reads and writes its files, and runs small Python scripts that write the database, build the dashboard and handle the Excel round-trip. Alongside it on the laptop: the `claude` command (used by the assistant), Python 3, and Chrome or Edge for the dashboard, which the local live server serves. Apart from Claude itself, no service outside the laptop holds project data.

## Storage and front end

Decision: hybrid. A SQLite database (`tracker.db`) is the record; an Excel workbook exported from it (`tracker-view.xlsx`) is where you browse and edit; a single HTML dashboard, served by the local live server and opened in Chrome or Edge, is the web interface.

| Option | Strength | Weakness | Status |
| --- | --- | --- | --- |
| SQLite record + Excel round-trip + HTML dashboard | Rules enforced by the database; safe to write while you work; change history and search built in; familiar Excel editing | Raw database needs a tool to inspect (the export and dashboard cover this) | **Chosen** |
| Excel workbook as the record | Familiar, edit anywhere | Breaks if edited out of shape; can't be written while open; no history | Superseded |
| Markdown files + Obsidian | Readable, linked notes | Weaker reporting; extra install | Not chosen |
| JSON or CSV files + local web app | Simple, fully interactive | Awkward to edit by hand; no enforced rules | Not chosen |
| Linear (cloud) | Built-in health updates and views; official Claude connector | Data leaves the laptop; IT approval | Deferred |

**How the dashboard works**

- **v0.22 redesign** (after a UX review against NN/g, Stephen Few, Material 3 density guidance and PMO practice). Single source of design truth: dev/reference/dashboard-reference.html — one working file with every view and component.
- **Navigation:** a fixed compact rail — Today, Projects, Work, Review, Files; Activity and Settings at the bottom; Help with ?. Top bar: search (⌘K / Ctrl+K), live status, last sweep and data time, Ask creaite (also /).
- **Today (home):** a one-sentence briefing; reminders as small dismissable notes; Needs your decision (routine items approvable in place), Your commitments (overdue and due soon), Changed since your last visit; then the portfolio with health, evidence (overdue actions, Urgent risks, milestone slip) and an 8-week trend.
- **Project cockpit:** health with reason and evidence, milestone timeline, actions due, top risks with responses, recent decisions, current state, and report drafting.
- **Work:** Actions, RAID and Decisions as tabs with saved views (Mine, Due soon, Overdue, No response yet…), owner filter and column chooser; title-first lists with few columns.
- **Editing:** a click opens a non-modal detail panel beside the list; E or a double-click switches it to a visibly different edit mode; Save applies immediately with Undo (auto-apply). No click-to-edit cells and no modal dialog.
- **Review:** proposals grouped by project, keyboard triage (J/K, A, R, E, X), batch approve or reject, Approve all routine; individual-approval items labelled.
- **Activity:** every change, newest first, with Undo.
- **Visual rules:** dense and calm; colour only for exceptions (red for Urgent, overdue and off track; amber for at risk); one quiet tag style; no floating buttons. Material 3 tokens with density applied.
- **Included from v0.21:** live server (red alert when down), Files tab, Ask creaite panel, Help, owner picker, client messaging rules, actionable sources, reminders dismissal, column resizing and 50-row frames, Settings content (now split into Preferences and Data admin).
- **Added in v0.24 (built from the backlog):** milestones with a timeline, percentage complete and dashboard editing (FR-53); current state first, in rich text with images (FR-54); Back and Forward with links between projects and their items (FR-56); named themes (FR-57); Work filters by project and priority with column reordering (FR-44); review detail lines and learning from project choices (FR-43, FR-14); Ask creaite chat history, autocomplete, Stop, resizable panel and runs that survive closing the page (FR-36); "Run report now" on reminders (FR-27); the installed version and updates in Settings (FR-55).
- Reports are per-project Word documents in `reports/`. A snapshot of each build is kept in `system/history/`.

**Excel round-trip**

- After each apply, `tracker-view.xlsx` is regenerated from the database: one sheet per record type, plus a Review sheet of pending items.
- IDs, sources and change stamps are locked; everything else is editable. New rows are added with a blank ID.
- "import excel" compares the workbook with the database and stages only the differences as a normal proposal.
- The database stays the source of truth: invalid edits are flagged, rows deleted in Excel are offered as Cancelled rather than removed, and changes made in both places since the export are shown side by side for you to choose.
- The export never overwrites unimported edits; it pauses and asks you to import first.

## Operating model

The system runs as a Claude Code project in the Claude desktop app, with the dashboard served by the local live server. Claude does the reading and judgement and scripts do the writing; everything Claude proposes waits for your approval, while your own dashboard edits and decisions apply immediately (auto-apply, with Undo).

**Weekly rhythm**

1. First session of the day (from 07:00): creaite runs cx-sweep automatically if it is due; mail and Teams items arrive as proposals.
2. After meetings: drop transcripts in `inbox/`, or name the meeting, and say "process new minutes"; draft minutes and items are staged.
3. When convenient: open Pending review in the dashboard (or say "review"); edit, approve or reject. Dashboard decisions apply immediately, with Undo.
4. In Claude Code, "apply" writes anything approved there: documents are filed, items written, and the dashboard and Excel export rebuilt.
5. From Friday 12:00 you are reminded to run "weekly report"; client reports are reminded per project rhythm. Any time: ask questions in Ask creaite or run any step manually.

**Triggers**

Claude's proposals never reach the tracker without your approval; your own dashboard edits and decisions apply immediately (auto-apply, with Undo), and approvals made in Claude Code apply when you say "apply". The daily sweep is guaranteed by a creaite rule, not the app's scheduler: at the start of every session Claude checks the last successful sweep and, if today's (due from 07:00) has not run, runs it first. Optional scheduled tasks can run it earlier when the laptop is awake. cx-minutes is manual only.

| Job | Automatic | Manual command |
| --- | --- | --- |
| Daily database backup | First session of each day | — |
| Mail and Teams sweep (cx-sweep) | Session start when due (default from 07:00); optional scheduled task | "sweep", "sweep mail for ABC", "sweep the last 7 days", "sweep the \[subject\] thread"; Sweep in Ask creaite |
| Minutes (cx-minutes) | None (manual only) | "process new minutes", "process \[file\]", "process \[meeting\]", "re-extract"; Process minutes in Ask creaite |
| Review, apply, Excel import (cx-review) | None (your decision) | "review", "approve…", "apply", "undo last apply", "import excel" |
| Dashboard edits and decisions | Applied immediately (auto-apply), with Undo; held and applied later if the live server is down | Detail-panel edits, New, Approve/Reject (A/R), Save and approve, batch approve |
| Ask creaite (assistant) | None | /, ⌘J / Ctrl+J, app-bar or floating button; any question or instruction, run by Claude Code in the vault (writes confirmed in the panel) |
| Settings | Saved instantly | Dashboard Settings tab, or cx-edit ("set sweep time to 06:30") |
| Plain-English edits (cx-edit) | None | e.g. "mark ABC-A-003 closed", "add an action for ABC…", "move ABC go-live to 2026-11-20", "make ABC-002 client-visible", "add project DEF…" |
| Weekly report (cx-weekly-report) | Reminder (default Friday 12:00) | "weekly report", "weekly report ABC"; Run report now on the reminder |
| Client report (cx-client-report) | Reminder per project rhythm (default weekly) | "client report ABC"; Run report now on the reminder |
| Setup and health check (cx-setup) | None | "setup", "health check" |
| Update creaite (cx-setup) | None; never installs on its own | "update creaite", "undo update", "what version is creaite?"; Settings › creaite version |
| Live server | Health check every 30 seconds; red alert if down | `python3 system/scripts/live_server.py` (you start it) |
| Dashboard and Excel export | Rebuilt on every apply | "dashboard" |

**Reviewing and approving**

1. Every Claude run (sweep, minutes, Excel import, plain-English edit, weekly or client report) drops a batch into `system/staging/`; each item is pending, with project, values, source, match strength and flags.
2. Each session opens with a one-line summary of what is pending, plus any due reminders; the dashboard's Pending review tab shows the same.
3. "review" shows everything grouped by project: first a "Needs a project" section, then per project — draft documents, conflicts, individual-approval items (health changes, new decisions, new risks), then routine items. Items pending longer than the stale threshold (default 7 days) are flagged and never expire.
4. You decide in the dashboard (edit any proposal, Approve/Reject, Save and approve, Approve routine), in Claude Code ("approve 1–6, reject 7", "4: owner is Sara", "9 is DEF", "approve ABC weekly report"), or in the Excel Review sheet followed by "import excel". Bulk approvals cover routine items only — never minutes, reports, health changes, new decisions or new risks.
5. Draft minutes and reports can be edited in Word first: close the file, then approve it individually. creaite automatically checks the edited draft against what is staged and asks before updating; client reports are re-scanned for internal content; tracked changes are accepted and comments removed before filing.
6. Dashboard decisions are applied immediately (auto-apply); decisions made in Claude Code are applied when you say "apply". Each apply is one transaction covering items and document filing; undecided items stay pending.
7. "undo last apply" (or Undo in the dashboard message) reverses the most recent apply (database rows and file changes), returns its items to pending, skips anything changed since, and can be repeated.

## Data model

Raw sources sit in the vault; the structured record is `tracker.db`, one table per record type, linked by project code and back to sources by file name.

| projects | Code (3 to 7 capital letters or digits), name, sponsor, phase, health, health reason, next milestone, milestone date, active |
| milestones | ID (e.g. ABC-M-001), project code, name, baseline date, forecast date, status (Planned, Done, Missed, Cancelled), order, percentage complete (optional), source |
| actions | ID (e.g. ABC-A-001), project code, description, workstream, owner, priority, due date, status (Open, Delayed, Closed, Cancelled), raised, closed, latest update, milestone (optional), client visible, client messaging, source |

| updates | Week ending (Friday), project code, health, summary, key changes |

## Project identification

Every item gets a project from its project code (3 to 7 capital letters or digits) plus the register; anything ambiguous is decided by you at review, never guessed.

| Strength | Signals | Result |
| --- | --- | --- |
| Strong | Project folder under projects/; Outlook project category; \[CODE\] in subject, meeting title or file name; registered Teams channel | Assigned |
| Medium | Stakeholder or sender unique to one project; client email domain; alias; two or more project keywords | Assigned, flagged (?) |
| Weak or conflicting | Single keyword; shared stakeholder; signals pointing to different projects | Marked Project? for you to decide |

- Items are matched one by one, so a cross-project meeting or email splits correctly.
- For meetings, both the meeting title and the transcript are checked; a meeting covering several projects is filed in each of them.
- Server-side Outlook rules categorise project mail by subject code or sender domain, even with the laptop off; cx-sweep treats a project category as a strong signal.
- When you resolve an ambiguous item, Claude (or the dashboard's "Remember this") offers to add the deciding signal to the register, so matching improves over time (FR-14). The register's optional **Senders** and **Exclude** columns hold individual addresses and words that rule a project out.

## Portability

creaite is moved by copying the vault; a new machine needs only the Claude desktop app and the `claude` command, Python 3.9 or later, the docx skill, Chrome or Edge, and a Microsoft 365 reconnect, then "setup" (cx-setup; NFR-12, in three tiers since v1.6.1). Scripts run through `system/scripts/run`, which picks the newest Python 3.9 or later, however many are installed (FR-173). The launcher and the login agent are optional macOS conveniences, outside the vault by design, and are made again on a new machine (FR-183).

| Machine-level item | How the vault covers it |
| --- | --- |
| Python libraries | Pure-Python copies bundled in `system/scripts/vendor/` (openpyxl, jinja2 and dependencies, MIT/BSD); no pip installs; every file checked against `vendor/manifest.json` by `doctor.py` (FR-174, v1.6.1) |
| Fonts and dashboard libraries | Roboto (Apache-2.0) bundled in `system/templates/vendor/` and inlined; Tabulator or Chart.js only if a view needs them |
| Daily sweep and backup | Creaite rules at session start, so no machine-level scheduler is needed; the optional morning sweep in `system/config/schedules.md` is created by cx-setup |
| Permissions for unattended and assistant runs | Project-level `.claude/settings.json` inside the vault |
| File paths | Defined once in `system/scripts/paths.py`, relative to the vault root; `doctor.py` fails on any absolute path |
| Claude app and command line, Python, docx skill, Microsoft 365, Chrome or Edge, FileVault, vault location outside synced folders, backup location, starting the live server | Installed or set once per machine (`dev/SETUP.md`, Mac first); cx-setup checks each and lists anything still to do |

- `system/scripts/doctor.py` checks the environment, database integrity, bundled libraries, paths and extraction exclusions; cx-setup runs it first.
- `dev/` is not needed at runtime: it can be hidden for a tidier root (Mac: chflags hidden dev; Windows: attrib +h dev), or left out when copying creaite to run elsewhere. system/ is never hidden, so the database and backups are never missed when copying or backing up.
- The two-week live trial includes a portability test: copy the vault, follow `dev/SETUP.md` on the copy, confirm everything works.
- A new version reaches a vault as a release zip (FR-55), never by copying files by hand; a brand-new vault gets its root `CLAUDE.md` from `system/templates/vault-CLAUDE-template.md`.

## Assumptions, risks and open questions

**Assumptions**

- The laptop is a Mac (primary platform); the Claude desktop app is installed, and the `claude` command works in Terminal and is signed in
- Python 3.9 or later is available (`python3`; SQLite is built in; other libraries are bundled in the vault)
- Anthropic's docx skill can be installed in Claude Code and fill Word templates
- Microsoft 365 mail, Teams and calendar tools are available to Claude Code, including headless runs
- Teams meeting transcripts and chat can be retrieved for a calendar meeting, or downloaded by organisers and attendees
- Chrome (or Edge) keeps read-write folder access for the dashboard — verified in Chrome on 2026-10-03 with no prompt after reload; Safari is not used
- A local server on 127.0.0.1 is permitted — confirmed by IT
- Project names or codes appear consistently in subject lines, channels and file names

**Risks**

| Risk | Mitigation |
| --- | --- |
| Microsoft 365 search unavailable in Claude Code | Minutes-only operation until resolved; fallback is an open-source Microsoft 365 MCP server, with IT approval |
| Laptop asleep or app closed at scheduled time | Launch Claude at login; missed runs caught up at next session |
| Scheduled runs blocked by permission prompts | Allow rules for the vault and scripts; tested in build step 6 by cx-setup |
| Laptop loss or failure wipes the vault | Encrypted drive plus approved local backup location; with projects in OneDrive, the project files are already there and a closed daily backup zip of what rebuilds the vault is kept beside them, checked weekly and restorable from Settings › Health (BL-323) |
| OneDrive is signed out or a file is online-only (projects folder only) | creaite carries on from the vault; online-only files are never read or downloaded; `doctor.py` reports the folder, the missing folders and online-only files; setting the Engagements folder to Always keep on this device avoids it |
| Excel export edited out of shape or with invalid values | Import validates every change against database rules; invalid edits are flagged, never imported |
| Excel edits lost or conflicting with automated changes | Export pauses while unimported edits exist; conflicts shown side by side at review |
| Database harder to inspect by eye | Excel export, dashboard and plain-English questions; daily backup copy |
| AI mis-attributes an action or owner | Review step before apply; source reference on every row |
| Duplicate rows | Processed-files log and a dedupe check in each proposal |
