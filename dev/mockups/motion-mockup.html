Motion for creaite: 38 ideas, all live

Everything here runs on creaite's own tokens and sample data. Each card says where it would live in the dashboard, how long it takes, and what it does when reduced motion is on. Cards play once as they scroll into view; Replay or the controls run them again. Slow ×3 is for judging the easing. The rule of thumb behind all of it: motion explains a change or confirms an action, never decorates.

Core: I'd build these

  • Motion tokens and one reduced-motion rule
  • Press, hover and focus feedback
  • Menus, panel and dialog enter and exit
  • Sliding indicator (List | Board, tabs)
  • Approve or reject: row collapses, Undo toast
  • Landing pulse on the row you arrive at
  • Board drag: card lift and column highlight
  • Row hover and J / K highlight
  • Copy confirmation, Review queue cleared
  • Banners sliding in (server down, VIP)
  • Reorder and board moves (FLIP)
  • Group collapse (BL-129)
  • Skeleton while the live server loads
  • Count-up, bars and ring once on page load
  • Changed values flash after an apply
  • Sweep progress and ask creaite's typing dots

Extras: nice if cheap

  • Checkbox tick and bulk bar (BL-122, BL-124)
  • Filter chip in and out
  • Saved tick on edits
  • Sparkline draw-in
  • Status dot ripple when health changes
  • Today's "now" marker
  • Staggered reveal on first paint
  • Theme switch fade
  • New since your last visit dot
  • Scroll-linked header shadow and progress
  • Word-by-word reply streaming
  • Ask button sheen

Rarely: look, then leave

  • Cursor spotlight cards (once, on a hero card at most)
  • Rotating gradient border (ask creaite input, on focus only)
  • Floating empty-state icon
  • Anything looping while idle, parallax, bounce, page-wide fades, confetti on approve

The house rules I'd write into dashboard-spec.md

  1. Three durations, three curves. 120 ms feedback, 200 ms state change, 320 ms layout; 520 ms only for numbers and bars. Exits take about 75% of the entrance.
  2. Only transform and opacity (plus grid-template-rows for collapse). Never animate width, height, top or left on a list.
  3. One-shot, not looping. The only loops allowed are a spinner, the sweep hairline and ask creaite's typing dots, each while something is actually running.
  4. Never delay the user. Animation runs alongside the state change, not before it; Esc, Apply and keyboard moves are instant to act on.
  5. Don't animate bulk or live updates. More than about 12 rows changing, or a live-server refresh while the user is scrolling or typing (BL-120), swaps with no motion.
  6. Reduced motion = no movement. Slides and scales become instant or a plain 100 ms fade; counts show the final number; loops stop. One rule in the stylesheet plus one flag in the script helpers.
  7. Colour tokens only, so every theme (default, Brightwater, dark) animates correctly with no extra work.
  8. Cheap to ship: almost all of this is CSS inside the existing dashboard.html; the scripted parts (count-up, FLIP, collapse) share about 40 lines of helper.
