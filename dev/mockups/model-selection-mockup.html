How this keeps it simple

  • Grades, not 30 settings. Three choices cover every feature; a feature is moved only under an override.
  • Honest about limits. Greyed providers say "Available soon"; features that need tools say "Claude only"; nothing silently falls back.
  • Safe by default. Best is fixed; confidential stays on Claude; keys live in the keychain; cheap results are checked.
  • Visible. One line of use by grade, and the reset time.

What the build has to settle (engineering, not yet checked in code)

  • creaite's runs go through the signed-in claude command. OpenAI and Gemini do not speak Claude's API, so they need a translating gateway (such as LiteLLM or claude-code-router) or a small direct call for the one-prompt features. I propose the direct call for the "Any connected" rows first; the tool-using runs stay on Claude.
  • Keys: macOS keychain, read by the live server only; never in a run's environment that Claude or a tool can read; the guard and backup rules apply.
  • Gemini's free tier and any "free" host may keep or review prompts: that is why free models are greyed and never for confidential text. DeepSeek and Grok are greyed for the same reason, plus data location.
  • This is an Opus + review build (run launch, environment, secrets).
