Which model does what

creaite sorts every feature into one of four kinds of job. Pick a model for each kind. Each row says what the job needs, so you can choose sensibly; the recommended model is marked.
How creaite decides which kind of job something is
  1. Does it need to use tools (read your mail, files or the tracker, or run commands)? Then it needs a model that can.
  2. Would a mistake be costly (the files that protect your data, who may write what)? Then it is the highest-stakes kind.
  3. Otherwise, is it one prompt in and text out, and must it keep dates, numbers, names and IDs exact? Short ones are quick edits; longer ones are writing.

The connect journey

  • 1. Connect… on a provider card. 2. Choose how (an API key; Claude can also sign in with a subscription). 3. Paste the key: stored in the keychain, never shown again; a plain warning that text leaves the laptop. 4. Test and connect: creaite asks the provider which models the key can use. 5. Tick the models to offer. 6. The provider shows Connected and its models now appear in the lists below. A wrong key says why (step 5 on the strip) and keeps the box open.
  • Disconnecting removes the key from the keychain and takes the provider's models out of the lists; anything set to one of them goes back to the recommended model.

Rules that stay in the page's logic

  • Choosing a weaker model than recommended asks first and lets you accept (step 6).
  • Models shown are only those of providers you are signed in to; greyed providers are listed as "Available soon" and offer nothing.
  • A job that needs tools lists only tool-capable models: today that means Claude. If OpenAI is not tool-capable in creaite's runs, it does not appear in that row.
  • I removed "Safety and cost" as asked. Two things it held now need a home, tell me where: the confidential-material rule (the connect box says it is never sent unless allowed) and the "retry on a stronger model if a date, number, name or ID changes" check.
