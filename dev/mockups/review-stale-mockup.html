Review: age that means something

Every proposal in Review carries a "Stale · 12 days" label, and the header says "4 stale" of 4. When everything is old, the label tells you nothing and the eye skips it. Two ways to show age so that a flag means "this one is different". Switch the sample data to see how each copes with a mixed list. Fictional data, desktop only.

Sample

What changes in both

  • The word "Stale" goes. A number of days is a fact; "stale" is a judgement, and it was applied to everything.
  • The age is always readable ("12 days"), but only an outlier or a group heading draws the eye.
  • The threshold (today 7 days) stays a setting; nothing else about approving changes.
  • Screen readers read the age as text on the row, not as a coloured chip.
Recommendation: A. Review already groups by project, and a second grouping by age would fight it. A keeps one list, keeps age readable on every row, and speaks only when something is different: a single line when everything is old ("All 4 waiting more than 7 days. Oldest first") and a marked row when only one is. B is clearer for a mixed list, but when all are old it is one big group with a heading that says what the rows already say.
