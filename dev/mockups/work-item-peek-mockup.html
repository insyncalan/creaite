What Plane does

  1. Click a row, the item peeks over the page. No navigation; the list is still there and clicking another row swaps the item. A full-page view is one icon away. The top-left icons are close, expand and (it looks like) a peek-mode switcher. Plane's tutorial: "Click anywhere on your work item row. Side panel opens showing details without leaving the main page."
  2. The five fields people change most sit directly under the title. State, priority, assignees, start and due date used to be a flat list in a right-hand rail; the April 2026 redesign moved them into the centre column after telemetry showed they are the most edited. Empty ones show as quiet prompts ("Add assignees", "Start date") rather than empty boxes.
  3. No view mode, no edit mode. A work item opens straight into editable; there is no read-only first screen and no action to start editing. The title and description are the editor itself (a rich-text surface); properties are chips that open a picker on click. Nothing is submitted. The only trace is a "Last edited by … 3 days ago" line. This is from your screenshots and Plane's write-ups; I could not read the source or the full blog post, so how it debounces saves is an assumption.
  4. Everything else is folded away. "Properties › Details" is collapsed, "Project structure" (Cycle, Modules) sits below, then created and updated stamps, then an activity feed with All, Activity, Comments, Updates, Transition and History tabs.
Sources: Plane docs, work items · Meet the new work item detail page · Plane University, layouts

How it maps to creaite

  1. new Overlay, half width. Replaces the 420px panel that pushes the page, and BL-80's "widen to half while editing". The page behind stays put.
  2. changes It opens already editable. Today an item opens read-only and you press Edit (E) to get a form, then Save or Cancel. Here there is no view state: the title, the key row and the free text are live the moment it opens, with no Edit, Save or Cancel. A value commits when you pick, press Enter or leave the field. Each commit is written to staging as a proposal, exactly as Save does today. ⌘↵ (Ctrl+↵) works as it did before: it commits the field you are in, applies everything staged and closes the panel. The pill at the bottom is the honest part: nothing reaches the tracker until Apply, and Undo last works per change.
  3. new Key row. Actions: Status, Priority, Owner, Due. RAID: Status, Priority (calculated, so read-only), Owner, Due, with Impact and Likelihood underneath. Decisions: Status, Decision maker, Needed by or Date made.
  4. changes BL-154's "More fields" becomes Details. Same fields, same rule that it opens by itself when something in it has a value.
  5. kept The rules. Closing sets the closed date; a made decision can't go back to pending; client-visible needs messaging before it saves; source on every row. Try each.
  6. changes BL-173. It says the item panels keep their current behaviour. This would reverse that for item panels, so it needs its own backlog item.

Anatomy (turn on the numbers)

  1. Toolbar: close, expand, previous and next, save state, copy link, more
  2. Title: plain text that is also the editor; hover tints, focus tints, no box
  3. Key row: the fields changed most, as chips that open pickers
  4. Free text: Latest update (actions), Mitigation action and its variants (RAID), Reasoning (decisions)
  5. Details: folded; opens itself for client-visible or when the form would have
  6. Activity: Activity, Updates and Source tabs from the change log, the updates table and the item's source
  7. Staging pill: the one place the approval rule shows
  8. The panel itself: overlays the page; click outside or Esc closes it

Decisions for you

  • choose One proposal or many? Each edit as its own staged proposal is simple but noisy. I would merge edits to one item into a single proposal until you apply.
  • choose Comments tab? creaite has no comments table. I left it out; a Notes tab would be new schema.
  • choose Review items. Proposals in Review should keep an explicit Approve and Reject footer, with the same layout above it.
