# Minutes style (Alan's format)

The layout is fixed by `system/templates/minutes-template.docx` (built from Alan's approved sample: Brightwater wordmark, Calibri body in Charcoal, section headings with a Signal Green rule, no cover page). This file covers what goes in it. Adapted from Alan's `minutes-adhoc` skill.

## Language and dates

- **British English** throughout (organise, prioritise, programme, sceptical, levelling).
- **Header and status line:** long dates, e.g. "30 September 2026, 12:00–13:05 (UAE time)". Times are always UAE time (UTC+4, no daylight saving), in 24-hour format. Teams transcript headers and Microsoft 365 calendar times are UTC: add 4 hours. Never show UTC.
- **Action Items deadlines:** DD-MM-YYYY, like the tracker (e.g. 09-10-2026). Work the date out from the meeting date ("by Friday", "next week" = that week's Friday); if it can't be determined, write "Not set".
- Never invent names, numbers, dates or outcomes.

## Placeholders (`docx_tools.py fill`)

| Placeholder | Content |
|---|---|
| `MEETING_TITLE` | Meeting name (calendar entry, else transcript title) |
| `STATUS_LINE` | `Draft, generated by creaite on <long date>. Not yet reviewed.` |
| `MEETING_WHEN` | `<long date>, HH:MM–HH:MM (UAE time)`; omit the end time if unknown |
| `ATTENDEES` | Grouped by organisation: `Name, Name (Company); Name, Name (Brightwater)`; add `Absent: …` only if stated. Organisation from the calendar invite domains, else only if the transcript makes it clear; otherwise names alone |
| `SUMMARY` | List of 3–5 short paragraphs (prose, not bullets): the headline per topic, in the order of the Updates, ending with next steps |
| `UPDATES` | `[{"heading": "<topic>", "items": ["…", {"flag": "PRIORITY", "text": "…"}]}, …]` |
| `DECISIONS` | List: `<decision> — proposed by <Name>; agreed by <Name or the group>` (or `no objection raised`, or `tentative, pending <Name>`) |
| `RISKS_ISSUES` | The **Risks, Issues, Assumptions & Dependencies** section. List: one line per staged RAID item, starting with its type and worded exactly like the staged description: `Risk: <event> → <impact>`, `Issue: <the problem>`, `Assumption: <what is assumed>`, `Dependency: <what we depend on, and on whom>`; optionally `— raised by <Name>` |
| `ACTIONS` | `[{"A_OWNER": "<Name> or TBC", "A_TEXT": "<verb-first task>", "A_DUE": "DD-MM-YYYY or Not set"}, …]`, worded like the staged actions |
| `OPEN_QUESTIONS` | List: `<question>? Raised by <Name>; <status — unresolved / who needs to weigh in>` |
| `SOURCE` | `Teams transcript, <long date>` (plus `and meeting chat` if used) |

The consistency check at approval, and "re-extract", read Action Items (owner, task, deadline), Decisions and the typed RAID lines, ignoring the text after " — proposed/raised/agreed". Keep them aligned with the staged items; a RAID line without a type is treated as a risk and flagged.

## Writing rules

1. **Group by topic, not chronologically.** Filter hard: drop small talk, repeats and dead-end tangents. Keep enough context that someone who missed the meeting understands why a conclusion was reached. Where real disagreement shaped the outcome, name the positions before the resolution.
2. **Executive Summary first:** several short paragraphs of flowing prose, the part busy readers read in full. Name the headline development per topic in a compact clause.
3. **Updates:** a heading per topic, then concise bullets, attributed to named people from the transcript's speaker labels (or chat senders). If speakers are generic ("Speaker 1"), use those labels; never guess names.
4. **Flags, sparingly:** about a quarter to a third of Update bullets at most; infer from substance, not keywords. Flags appear only in Updates.

   | Flag | Use when |
   |---|---|
   | PRIORITY | Explicitly called out as what matters most now |
   | ACTION | Work actively being scoped or planned (not a formal action item) |
   | FLAG | A watch item: a risk, gap or tension not yet blocking |
   | BLOCKED | Cannot move until something external resolves |
   | SUPPORT NEEDED | Needs a decision, resource or help from outside the discussion |
   | NEW SCOPE | Scope added to existing work |
   | NEW | A new initiative just starting |
   | ON TRACK | Explicit reassurance on something that could be in doubt |
   | HIGH RISK | More severe than FLAG: could derail the topic |
   | DONE | Just completed or resolved |

5. **Decisions are not actions.** A decision can stand alone; list a task under Action Items only when something must be done. Attribute both to named people.
6. **Hedging** ("I think", "probably", "tentatively") makes a decision tentative: say so ("leaning towards X, pending Name's sign-off") in the summary and in Decisions.
7. **Meeting chat** is a real source: links, numbers and corrections typed but not said belong in the minutes. Trust the transcript where they disagree, unless the chat is a deliberate correction.
8. **Confidential or restricted** content is left out of items unless Alan says otherwise.
9. If the transcript is partial (it ends before the meeting does), say so in `SOURCE` and in the chat reply.
